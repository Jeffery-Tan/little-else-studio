# US 视频制片室（us-video-studio）

US 视频与图文前期策划的本地独立工作台：用户在应用内与主 Agent 对话，主 Agent 按任务调配创作角色并自检，用户决定方向与脚本。独立审核 Agent 已停用，历史审核记录保留。学习记录处理带货 Skill 的证据与待审差异；参考视频可只分析、只生成针对当前商品的提示词，或继续完整策划。支持本地审阅包，以及由用户在同一工作台「分镜 / 成片」中明确提交的 Codex 图片与百炼 Wan 视频任务；不自动发布或判断市场效果。

功能代码、当前服务加载和真实能力验收分开记录，统一见 [实现与验收状态](docs/product-improvements.md)。本页描述当前代码功能，不能单凭页面出现按钮判断对应后端已加载。
HTTP 入口在 [server.py](studio/server.py) 组合依赖和本机安全边界，学习交付、项目、素材、决定、连接与任务路由分别在 `studio/http_*.py`；测试客户端使用环回地址，与正式 Host 规则一致。
创意与声画验收按[分层任务集](docs/creative-quality-validation.md)开展；离线工程测试只覆盖状态与安全，不代表真实模型或成片质量已验证。

对话中的作品决定绑定本次真实消息和页面已提供的准确版本；普通 A/B/C 待选卡不能把一句“行”自动变成采用推荐项。采用与接续分别保存，“采用 B，暂时别继续”会采用并暂停。只有真实任务回执存在才表示后续已启动；旧页面或无法核对的消息会要求重新明确。接口和短答边界见[对话控制模型](docs/conversational-control.md)。

会话与角色任务复用原事件记录：主任务、子任务、原话来源及准确产物回执可以追溯；中途多条消息逐条处理，进度查询即时回答，停止不自动接续。刷新与切项目保留完整草稿、作品目标和已上传附件用途；未上传文件会提示重新选择。重启只保留中断与恢复入口，不重发模型或生成请求。此轮借鉴 Harness 机制改造当前 Python 运行层，尚未切换到官方 Harness runtime，详见[架构实施说明](docs/deepseek-harness-review-20261003.md#实施后的路线选择2026-10-03)。

媒体交付区分输入齐备、等待授权、执行中、失败、结果待核实与实际完成；准备了确认卡仍未交付媒体。镜头修改后，旧确认失效，单镜和整组提交都会在提供方调用前复核当前准确输入；原任务结果不明时，新制作稿也不能绕过核实。

人物与场景设计沿用现有创作流程：导演确定美国受众处境与人物关系，素材统筹在素材计划中保存共同人物、服装、场景、道具及连续性设计，脚本逐镜引用同一身份。制作端将设计与已采用分镜编入实际发送的描述，确认时同时展示全部参考图及用途。图片最多五张参考图，视频继续使用一张获批首帧；商品参考不自动继承供应商模特或环境。无人画面允许明确设计为纯商品细节。方法与字段见[共同视觉设计方法](docs/methods/visual-design.md)。

历史项目、旧稿与已生成结果保持可读；缺少共同设计或准确镜头引用时，需要先补素材计划、更新并采用脚本，再准备新制作输入。共同设计换版会按现有阶段依赖使脚本与制作输入失效；替换首帧后，旧视频输入与旧费用确认也不能继续提交。不会自动改写历史作品、生成设计参考图或增加用户逐项审批。字段与指纹校验不能证明真实画面质量，美国生活语境、人物一致性和商品准确性仍需实际图审。

**直接在对话中说想做什么，附上视频或粘贴TK链接。** 首页和项目对话都有「商品图片/视频」「参考视频」两个上传按钮，点哪个就带入对应视频用途，选完仍可在附件上修改。商品视频补全商品信息；参考视频才拆解表达。粘贴链接时说明“用这条商品视频补全商品信息”或“拆解这条参考的表达”；裸链接用途不明时主制片问一句。上传本身不分析；素材页的视频卡片与预览都可直接点击「分析视频」，按用途确认一次视频观察调用；已有有效观察先打开记录，未完成的只分析参考任务复用原任务。明确要求分析的商品视频链接会在当前对话任务中获取原片、做声画观察，并把商品候选留在素材区等待逐条核对采用，不自动成为商品事实或开始制作。主制片承接明确的参考分析、复刻或局部借鉴；自主创作无需参考。通过[百炼北京 Omni](docs/bailian-omni-and-tiktok-import.md)复用现有Wan连接；链接失败可上传原视频继续。已保存的原片和有效分析会复用。真实链接成功率与模型识别质量待验收。

参考任务完成后，项目内「参考拆解」按模型估计的时间段并排显示原视频、画面、声音及方法假设；点击片段可跳回原片核对。只分析项目在原「分析与参考」画布阅读，独立学习记录在来源区阅读同一拆解。创作项目可在该视图请主制片生成本品提示词，或手动编辑并保存版本；保存文字不启动媒体生成。原片观察和本品适配仍须分别核对，原片成交数据不会由视频分析推断。

已明确的用途回答只保存一次；模型漏填视频用途时，可沿原任务补齐一次来源信息，不要求用户重新选择。补齐前核对真实来源与附件用途，不能改变任务或收费权限。原链接、跳转后的链接和已保存文件仅在下载记录与当前文件指纹相符时共用原来源及有效分析，避免因换了表示方式而重复下载或分析。真实模型调用仍须按当前输入的观察准入执行。

[Codex 驱动工作台](https://github.com/Jeffery-Tan/e-business/blob/main/apps/video-workbench/README.md) 与本应用分别维护、互不写入运行状态；不自动迁移历史批准。业务采用状态仍以 [US 线路](https://github.com/Jeffery-Tan/e-business/blob/main/tracks/us/README.md)、[午餐包当前状态](https://github.com/Jeffery-Tan/e-business/blob/main/tracks/us/docs/lunch-video-current-state.md)及飞书 Tasks 为准。开发约束见 [CLAUDE.md](CLAUDE.md)，架构与运维见 [独立运行说明](docs/independent-runtime.md)。业务操作在本应用完成，Codex 桌面开发对话不作为后台执行器。

DeepSeek 对话调用设有单次 10 分钟总时限，覆盖连接等待与流式回复，保活消息不延长时限。原任务状态行显示已等待时间、是否正在接收模型数据和本次等待上限；这些统计不表示作品完成进度。超时停止本轮，不自动重试；点击停止或在执行中明确要求停止会撤销尚未接续的旧调整，刷新和重启不恢复取消任务。已有内容保留，继续时在原项目发送新指令。

## MiMo 模型入口

模型设置 → 添加模型服务 → 选择「MiMo · 小米」。官方地址与输出参数已预设，角色模型默认提供 `mimo-v2.6-flash`；填入 MiMo API Key 后保存，再自行选择需要使用它的角色。添加入口不会自动更换现有分配，未填写 Key 或未实际测试的连接不视为可用。

MiMo 可用于商品图片分析及原生视频声画理解。在模型设置的「图片理解」和「视频理解」分别选择 MiMo；正常对话中的多图观察使用前者，主制片、素材区、参考拆解和商品视频观察共用此选择，不需把主制片换成 MiMo。未选择时保留原百炼路径；MiMo 缺密钥或调用失败不自动切换服务。已有有效分析按原来源与模型标识复用，不因换模型重新收费。图片与视频理解独立于团队角色；图片默认保留百炼，显式选择 MiMo 后使用其自有连接与密钥。每次任务冻结配置版本，配置变化停止尚未提交的新观察，已完成观察保留。图片沿用自动压缩与每批 7,000,000 字节上限；协议依据 [官方图片理解](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/multimodal-understanding/image-understanding)（2026-10-08 核对）。

视频沿用 64 MiB 原件与 90 秒范围，默认 2 fps / default；本地 Base64 编码后须低于官方 50 MB 上限，工作台先将原始输入限制为 35 MB 留出余量。必要时压缩观察副本并保留原音轨，核对实际时长与音轨覆盖；原片保留。观察结果绑定原片、副本及时间轴，仍需核对。图片生成始终由 Codex CLI 调用工具处理，视频生成沿用原制作入口。依据 [官方视频理解](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/multimodal-understanding/video-understanding)（2026-10-07 核对）；离线测试不代表真实模型理解质量已验收。

2026-10-09 迭代增加对象画布、真实参考关系编辑、项目布局、批注汇总、实际结果检查、方法快照和有界任务队列。实现与验证边界见[独立工作台迭代](docs/workspace-iteration-20261009.md)。

## 创作工作空间

首页项目卡片的「删除」和工作台顶部「删除项目」会先显示项目名与影响，确认后移入回收站。首页「回收站」可恢复全部对话、素材与成果；删除不清除磁盘文件或历史调用记录。正在执行的项目需先停止并等待结束，删除操作不会暗中取消任务。已删除项目从列表和切换器中隐藏，并拒绝新任务。

首页从一句话和可选参考图片/视频开始，自动建立创作记录；素材上传完成后才发送第一轮对话。Agent 在对话中用简短推荐选项和自由补充确认重要意图。桌面工作台中央作品画布查看当前方向、素材、脚本与制作结果，右侧保持连续对话；窄屏可切换作品与对话。方向与脚本的准确版本决定、澄清和修改意见可在对话或作品阅读页完成，复用同一决定组件与服务端写入点。确认方向后接续完整方案，确认完整方案后接续分镜输入准备；若决定已保存但任务未启动，对话区会显示继续入口。已创建任务的重试只读取原任务，不自动重发模型调用；实际媒体生成仍需明确确认。版本与哈希保留在后台，旧审核记录只供折叠追溯，旧项目与准确版本审批保持兼容。

创意方向缺失或因上游资料变化而失效时，页面提供绑定当前资料版本的「生成／重做创意方向」。点击后只派导演完成一次方向任务，并停在 A/B/C 供用户选择；资料已变化会提示刷新，不会拿旧页面命令继续。自由对话中的新反馈仍由主制片理解并保存到当前项目；资料齐备后由程序接续派工。失败不会自动重试或触发媒体生成。

对话按轮展示已实际发生的角色旁白和关键操作，执行中在该轮显示当前步骤；刷新后仍可阅读已保存进展。顶部任务状态只提供简短状态与停止、恢复入口；「团队工作记录」保留完整分工、操作和阶段内容入口，技术诊断默认折叠。角色处理开始事件在模型等待与工具执行前记录；不推算完成百分比或补造旧记录。

「灵感与方法」默认从参考画面进入，Skills、经验、反馈和本轮上下文仍可访问。版本哈希、调用记录、连接协议与费用参数默认收进详情；运行失败与审批要求仍明确显示，未知用量不成为创作待办。

项目列表、作品区、制片对话与主制片都读取原项目事实与派生摘要，区分“内容已保存”和“等待采用”。新稿共用结构化内容生成正文；问题明确责任人与处理时机。历史审核状态仅用于追溯，不阻断新版决定。交互演进与旧稿兼容的历史记录见 [制片交互架构](docs/creator-interaction.md)。

项目内按作品阅读：顶部从已记录的需求、作品和任务推导最终交付、当前作品与一项主要动作，原始长需求可在详情查看；默认以「需求与素材 → 共同人物/场景及分镜表 → 本版图片与视频结果」横向展示在同一张创作画布，右侧保留对话。支持缩放、平移、适配全部节点和聚焦方案；点开详情后可返回原视图。结果只与准确脚本版本、指纹及后台 shot_id 对应，历史输入与旧图从制作记录查看，不混入本版镜头。图文只呈现相关图片与文案，只分析参考展示需求与分析入口，独立学习仍沿用学习工作台。待选与已采用的方向都保留作品卡，已采用方向优先展示、其他方向可展开比较；旧稿只有原文时直接展示原文，不补造结构或迁移批准。脚本按实际内容展示画面与动作、声音、台词或图内文案；没有台词的段落不会仅凭空字段被说成“无口播”。准确版本的画面、文字与声音可点选后在对话中提出修改；已取回的图片和视频可针对具体结果及当前播放时间点反馈。后台拒绝旧版本、不存在的内容位置或文件字节不符的媒体目标。生成失败时，可一键将准确制作稿及尝试交给主制片诊断并提出修正，也可自行描述问题；这一步不生成媒体、不沿用旧图审或费用授权。手动修改 Prompt 留在高级入口；新尝试失败或待核实，上一次仍有效的生成结果继续作为可查看作品，本次尝试状态另行显示。图片、视频结果优先展示，制作描述、历史检查依据和尝试记录按需展开；生成结果不明时先核实原任务。已有创作项目临时只分析新参考时，最终视频目标仍保留，本轮先展示参考报告。发布文案是新脚本的可选正式字段；视频旁只将脚本版本和指纹均匹配且完整的文案称为同套交付，新版文案单列为尚未对应当前视频，旧稿缺少时显示缺口，不从示例或制作 Prompt 补造。生成仍需逐次核对参考图、实际范围和费用。

## 启动与检查

本仓库是唯一开发与运行入口，电商旧入口已退役。新工作台从 Git 外新空目录启动：`scripts/start.ps1 -DataRoot <new-empty-directory-outside-Git> -AllowNew`；应用内启动器是实现细节，不要求导入旧项目。四个 US Skills、学习库、案例及方法随本仓库维护，无须外部业务根。引用经营事实时可额外传 `-BusinessRoot <E-commerce-root>`；它不会改变知识读写路径。旧路径引用仅供来源追溯，具体边界见 [迁移说明](../../docs/migration.md)。

左侧「灵感与方法」已接入三项创作 Skill、原案例与方法库、研究来源和反馈迭代；独立学习记录另加载学习流程 Skill。Agent 可按角色读取[登记方法卡](studio/learning.py)，补救、视频输入与图文输入卡只提取稳定执行规则，原历史研究和反馈仍限人工审计或原资格过滤。实际角色输入保存快照；反馈绑定准确版本，先看差异再应用。视频输入与图文审阅包可在「本轮参考」打开，见 [学习迁移说明](docs/learning-migration.md)。

首页「独立学习」从一句研究意图与可选原片建立 `learning` Run。上传不调用模型；如需声画分析，在学习记录里单独确认参考分析。学习对话只能读取当前来源、比较合资格方法并提出待审变更，不能提交生产阶段或媒体生成。用户可只分析后结束，或核对提案差异后保存、拒绝。正式共享库当前仍为 v1：页面提供只读 v2 迁移预览及单独确认，迁移保存原字节备份；测试不改正式库。新创作项目的方法摘要按适用条件独立召回，使用记录只表示 Agent 声明，实际脚本与效果仍需验收。

真实运行数据必须位于 Git 外，使用 `STUDIO_DATA_ROOT` 明确选择。未设置时代码沿用历史 J 盘默认目录，它不代表当前电脑实际使用的位置；素材、台账、配置与凭据不得提交 Git。一个数据根只允许一个 Studio 写入进程；离线导入或恢复前停止该数据根的服务。

启动必须经 `scripts/start.ps1`（内部先跑 `studio.doctor`，会拒绝在已有写入进程或端口被占用时再起一个）。**手动 `python -m studio.server` 会跳过这些检查**，2026-09-30 就是这样起了一个指向默认数据根的服务：项目页打不开、报 `no such run`，而磁盘上的运行数据完好。三条硬性做法：

1. **数据根必须在同一条启动命令中显式传入**，例如
   `scripts/start.ps1 -DataRoot <new-empty-directory-outside-Git> -AllowNew`。
   不依赖上一条命令或另一终端设置的环境变量。
   启动后先用 `GET /api/runtime` 的 `data_root_id` 核对自己连的是哪一个数据根，再打开项目。
2. **正常代码更新由服务自行重载**。启动器保持一个监护进程，旧工作进程正常退出并释放
   writer 锁后才启动新版；不需要开发助手逐次执行停止进程命令。手动关闭整套服务时，
   仍须确认没有活动任务并一并停止启动器与子进程，不能只结束 venv 包装进程。
3. **起第二个服务前先看端口**：`Get-NetTCPConnection -State Listen | Where-Object LocalPort -eq 4760`。

### 对话即控制面

对话框是主要控制面：用户在对话里说出的决定就是决定，不需要再去别的页面点一次。设计与边界见 [对话控制模型](docs/conversational-control.md)。

- **创作决定直接生效。** 「采用 B」「这个脚本可以，继续」「第二镜换自然一点」这类无费用、可逆的决定，由主制片用 `read_user_actions` 读出当前真正等你决定的事项，再用 `propose_user_action` 指认你表达的那一件事；服务端重新推导候选、复核版本与指纹后经 `Pipeline.record_approval` 记录，后续工作随即开始。按钮点击与对话原话只是两种输入渠道，写入点与接续派生都只有一处。
- **有歧义就问，不猜。** 同时有两件事等你决定而你只说「行」时，系统会问一句清哪一件；「采用 B」需要真的说出 B，团队推荐的那一项不会替你做选择。没有点名选项时会反问，而不是替你选。
- **一句话里的额外要求不会被丢掉。** 「B 吧，但开头别那么像广告，生活化一点」会记录采用 B，并把你那句话原样作为下一轮指示；被采用版本的字节与指纹不变。模型改写的要求不会被当成你的话。
- **收费只推进到确认。** 自然语言可以把生成准备到「只差一次确认」——整组生成的请求（含「按这六镜生成吧」）落在对话区既有的确认卡上，显示范围与费用后由你点确认；在此之前不提交任何提供方请求。创作决定不会被自动升级成生成授权。

### Agent 与模型

当前执行与交互约束见[对话控制模型](docs/conversational-control.md#十二会话角色任务与完整输入2026-10-03)，修复结果见[整体架构审计](docs/agent-architecture-interaction-audit-20261004.md#修复与再次复核--2026-10-04)；[早期 Agent 架构审查](docs/agent-harness-review.md)保留为历史依据。角色保存准确成果后结束该角色本轮，主制片统一说明结果；不额外调用模型补写结束语。工具执行前核对本轮能力，派工无实际交付时明确返回未完成或失败。

主制片每条新消息重新确定工作范围，可找回本项目的旧对话；专业角色返工时拿到准确上一版与对应责任问题，并可补读登记方法。所有角色与模型设置页共用已声明的能力边界；主制片可按明确任务观察参考视频，素材区可显式做有限声画分析，但各专业角色仍只读来源标明的观察记录，不直接收到原视频像素或音频。模型理解质量仍需实测。每次调用的逻辑输入保存在 Git 外原 run 下的 `requests/<call_id>.json`，供本地指纹校验与诊断；记录失败不调用模型，不把快照用于跨角色或跨任务恢复对话。响应校验失败在原调用的 `agent_response_rejected` 事件中保存字段、类别和必要的指纹/JSON 错误位置，不保存原始响应或参数；界面区分提供方中断与格式异常，失败不执行工具或自动重试，实际收到的用量照常保留。

本轮明确交付目标可选需求整理、方向、完整方案、制作输入、整套生成结果、局部修订或只分析。任务结束时程序分别记录模型执行状态与交付状态：准确产物、相应独立检查或本轮修订计划缺失时列出具体缺项，不能把模型正常结束当作作品已交付。制作输入与整套生成结果按目标镜头逐镜核对（见[镜头身份与整套覆盖](#镜头身份与整套覆盖)）：一面镜头的草稿不算整套输入准备完成，一张图片不算整套分镜完成。同一缺项在没有进展的情况下重复出现时，程序停止继续催促并在任务状态里说明实际阻碍，不让主制片为了凑齐交付去重提一次可能已经提交的生成。只读跟进不要求新的制作产物；生成仍需原有用户确认。

素材页现支持视频画面分析：本地提取带时间点的画面，单次交给所选视觉模型观察，经采用后进入创作依据；不发送音频、不宣称完整看听。参考解释与商品观察分别整理，导演构思前即可读取。输入限制、评估样本和运行依赖见 [素材理解与参考迁移](docs/material-understanding.md)。

对话中的局部修改现可绑定准确旧稿和字段，由程序保留其他内容；主制片按依赖安排必要工作并自检。新版仍需用户阅读和采用，旧批准不迁移。支持范围与四点路线进度见 [按问题执行与局部修订](docs/problem-directed-revisions.md)。

任务运行时仍可在对话框发送补充或修改意见；「停止」是独立按钮。意见先保存，再按原话决定是否要停下手上的活：问进度不会中断正在进行的生成，明确说停就按停止处理，不会自动接上一轮新任务；其余情况结束当前一轮，由主制片读取原要求、顺序补充和已保存成果后继续。判断只按用户实际写了什么（`studio/steer_intent.py`），不按模型给这条消息贴的意图标签，因此一次选错的意图不会把后面的纠正一起锁死。点选脚本、草案或生成图后发送的意见会携带准确版本；若版本已变化，需重新选定，不会套到新版。已有媒体请求不会因插话自动重复提交。

在当前结构化脚本中点选台词、画面、声音或发布文案，可输入意见后点「按意见直接修改」。该动作仅修订所选字段，交编剧提交补丁；新版仍须阅读和决定是否采用。任务条和首页项目卡分别说清新版保存与用户待决定状态；历史决定标明所属版本。普通「发送」继续用于讨论。版本、原句或字段已变化时，页面与服务端会要求重新选择；历史纯文本脚本只支持在对话中讨论修改范围。

定向任务的 `revision_result` 报告局部新版是否保存；整稿是否可交付仍看 `deliverable`。任务记录保留准确版本供用户检查。

- **DeepSeek 官方 API**：选择 DeepSeek 后填写 API Key，地址与兼容参数由应用设置，不需要手填。可先点击「验证密钥与模型」，再把可用模型分配给角色；也可先保存，未验证状态会明确显示。默认提供 `deepseek-flash` / `deepseek-v4-pro` 选项，验证后以提供方返回的模型列表为准，既有模型不会被静默替换。更换 Key 或服务后旧验证结果失效。
- **连接验证范围**：只向固定官方地址 `https://api.deepseek.com/v1/models` 发出一次只读 GET，验证认证并获取模型列表；不生成内容、不提交业务资料、不保存输入的 Key、不改变角色绑定。成功不代表余额、文本生成或完整 Agent 流程已经实测。Key 仅在点保存时按原本机 DPAPI 机制持久化；关闭窗口清空输入。验证结果仅用于当前编辑会话。
- **DeepSeek 任务运行**：专用适配器启用 thinking，编剧使用 low，其他 DeepSeek 角色保留 high。编剧设置依据同一隔离案例的真实验收：high 超时，low 完成 16 段草稿；仍需核对内容，不保证每个任务都能按时完成。工作台不传 `max_tokens`，采用提供方默认输出额度，不继承通用兼容连接的 16K 上限（官方 2026-09-21 文档：当前思考模式默认 64K）。工作台默认不设全局 token 或美元额度；用量未知不阻断，调用照常记入台账；同一角色的当前循环精确保留工具往返和续写所需的私有推理字段，不进入用户正文或其他角色。新 job 从已保存对话与产物开启新的推理请求，旧助手回复作为标记的历史资料，不伪造旧推理字段或建立第二套可恢复私有会话；逐次逻辑请求诊断快照可能含本轮必要私有字段，不向其他角色提供。调用继续通过原用量台账和任务恢复边界。接口依据：[思考与工具调用](https://api-docs.deepseek.com/guides/thinking_mode/)、[模型列表](https://api-docs.deepseek.com/api/list-models/)（2026-09-19 核对）。
- **Anthropic / OpenAI 兼容 API**：填写服务地址、API Key 与该提供方的准确模型 ID。OpenAI 连接默认使用 `max_completion_tokens`；旧兼容网关可选择 `max_tokens`，不自动重试替换参数。Anthropic 地址可含 `/v1`；OpenAI 地址可含 `/v1`，勿填写具体 messages/chat/completions 路径。
- **价格**：可按连接、模型填写输入/输出价格及来源；空白保持未知，Codex 订阅用量不套用 API 价格。更换已有连接的地址或协议会清空旧价格，核实后重新填写。
- **保存**：仅保存配置，不调用模型；正在执行的轮次保留配置快照，下一轮才应用变更。更换地址或协议需要重新输入 Key。

| 配置入口 | 含义 |
| --- | --- |
| `STUDIO_DATA_ROOT` | 数据根；未设时使用上述默认目录 |
| `<data-root>/connections.json` | 站内维护的连接、角色绑定与 Windows DPAPI 加密凭据；不提交 Git |
| `<data-root>/config.json` | 循环限制与可选的旧版预算字段；未配置额度时不阻断调用 |
| `STUDIO_BASE_URL`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` | 旧直接客户端的兼容配置；新的站内连接不自动导入环境凭据 |

没有 `connections.json` 的新服务默认各角色选择 Codex CLI。已有旧版 `config.json` 的模型/端点不会自动迁移为站内连接；第一次正式使用前在页面确认角色配置。历史账目继续沿用原数据根；旧数值预算字段仍可兼容，当前不设额度可将两项预算字段置为 null。API Key 只在服务端加密存储，接口仅返回是否已保存，不写入浏览器存储、任务事件或模型上下文。

### Codex 登录 / 授权

在「模型设置」的 Codex 服务卡内查看登录状态；未登录时点击「登录 / 授权」，在系统浏览器完成官方 ChatGPT 登录，返回工作台后自动更新。流程使用本机 `codex login`，凭据仍由 CLI 自行保存，工作台不读取或返回密码、令牌及原始登录输出。依据：[官方身份验证说明](https://learn.chatgpt.com/docs/auth)。

打开设置和「刷新登录状态」只执行 `codex login status`，不调用模型、不查额度。已登录 ChatGPT 时不重复授权；已使用 API Key 登录时提示用户在终端自行确认切换，不自动登出或覆盖账号。未找到 CLI 时先安装，再刷新状态。

同一服务只允许一个登录流程，重复点击复用当前等待；模型任务运行时不能启动授权，授权等待期间不能新发起模型任务。登录最长等待10分钟，失败或超时后可手动重试；不自动启动第二次授权。关闭设置只停止页面查询，重新打开可继续查看；「取消本次登录」绑定显示的 attempt_id，只停止这次等待，不登出已经登录的账号。普通服务关闭会清理仍在等待的登录子进程。

接口：`GET /api/connections/codex/status` 返回受限状态、中文提示、登录方式和本次 attempt_id；`POST /api/connections/codex/login` 要求 `{"consent":true}`；`POST /api/connections/codex/login/cancel` 要求 `{"attempt_id":"界面实际显示的ID"}`。两个写接口要求本机同源 JSON，不提供 logout、令牌读取或账号切换接口。登录状态不证明实际生成或费用验收通过。

### 隔离界面预览

预览使用手写方案、审核和台账数字；它们不是实际创意结论、用量或批准。`scripts/seed_preview.py` 默认不复制商品素材，页面会明确显示缺失文件，适合检查决定、流程与降级状态；如需检查真实媒体排版，可显式传 `--media-root <商品素材目录>`，脚本先核对全部文件再复制。素材与演示文案未必是同一商品。脚本仅接受不存在的新数据根，拒绝覆盖已有目录。

在应用目录、专用 PowerShell 会话执行，下例目标目录必须尚不存在：

```powershell
$studioPython = Join-Path $env:LOCALAPPDATA 'LittleElse/Studio/runtime-venv/Scripts/python.exe'
$studioPreview = Join-Path $env:TEMP ('studio-preview-' + [guid]::NewGuid().ToString('N'))
& $studioPython scripts/seed_preview.py $studioPreview
$env:STUDIO_DATA_ROOT = $studioPreview
& $studioPython -m studio.server --port 4762
```

新版预览种子写入无凭据的 loopback 测试连接，全部角色都指向它，发送消息会在调用前阻断。旧预览目录不自动迁移；请使用新目录。不要在预览根添加真实端点配置或切换到 Codex。三个 fixture 分别展示方向待采用、脚本审核退回和全部完成；包含一个故意引用不存在文件的镜头，用于检查降级提示。停止服务后保留或按明确授权清理预览，不能据此删除其他运行数据。

## 界面与工作流

界面采用炭黑、灰阶与荧光黄绿，首页项目卡片、创作板和制片对话构成主要工作空间。主题在 [cinema.css](studio/web/cinema.css)，行为布局在 [style.css](studio/web/style.css)；使用本机字体回退，无外部字体、图片或前端框架依赖，支持窄屏和减少动态效果设置。

四个阶段为 `intake → direction → material_plan → writing`。需求整理呈现事实、约束和未知项；创意方向展示多个选项与推荐依据；素材计划说明可用素材与缺口；脚本呈现镜头时长、画面、台词和声音。`direction` 与 `writing` 由主制片自检后交用户决定；本应用尚无 `layout_preview` / `ad_preview` 渲染阶段。

- 桌面中央查看当前成果、右侧持续对话和就地决定；窄屏切换作品与制片对话。旧版本继续留在后台供准确绑定与追溯，主界面不列历史版本；素材抽屉支持预览和上传。
- 方案、分镜、成片采用关联的标签页与面板；键盘左右方向键、Home、End 可切换并移动焦点，Tab 只进入当前标签。
- 推荐不等于采用。用户明确选中方向再提交，批准记录保存 `selected_option_id`；后续角色读取实际选择。
- 退回修改需要意见；旧独立审核结论只供追溯，不构成采用门槛。批准仅覆盖该版策划，不授予生成、费用或发布权限。
- 同一版本只作一次决定：采用或退回之后，这一版不再出现决定入口，新版由团队按你的意见产出；历史审核退回不占用用户决定，也不要求覆盖理由。
- 决策草稿按运行、阶段和产物摘要保存在本机浏览器，并在对话区的唯一决定入口恢复。保存中阻止重复提交；冲突保留草稿，要求重新阅读最新版本。用户退回和上游失效不显示为完成。
- 费用入口展示真实记录的已知用量与待核实项；历史阶段用量是参考记录，不是下一次费用预测。

领域状态与业务措辞主要由 [vocabulary.py](studio/vocabulary.py) 提供，前端负责呈现与交互校验。历史审核结论只供追溯；当前主制片自检也不能替代用户决定或实际内容验收。

## 架构与版本契约

```text
浏览器 studio/web (REST 任务提交 + 进度重连；保留 SSE 兼容入口)
  → server.py
      → jobs.py：持久任务、幂等提交、取消、重启中断与单 writer 锁
      → connections.py：加密凭据、每角色路由与配置快照
      → pipeline.py：前置条件、尝试、审核、审批与失效传播
      → store.py：不可变产物、事件历史、摘要与原子写入
      → ledger.py：调用意图、结算与待核实用量
      → agents/orchestrator.py：主 Agent 循环
          → tools/dispatch.py：上下文隔离的创作角色
```

每份产物由 `<stage>-vN.md` 正文及 JSON sidecar 组成。`artifact-v2` 摘要绑定阶段、版本、正文、展示结构、摘要、证据、限制和依赖。结构化展示不是第二套事实；格式不可用时保留正文并记录降级，不能据此伪造可选方向或审批。

上游产物、已选方向、素材字节、外部观察或导入来源变化会使依赖产物失效，保留旧版本、审核和批准历史。素材存在只证明文件可读取，不证明模型理解了画面。历史 `body-v1` 仅可回放，继续制作必须生成可核对的 `artifact-v2`，不能复制旧批准。

新任务不派独立审核角色；主制片和执行角色在交付前自检，Jeffery 对准确版本作决定。写作者只获得当前目标、已采用方向和必要素材证据。任何 Agent 工具都不能签发审批或写用户批准。

服务取得数据根 OS writer 锁，离线导入和恢复 CLI 复用同一锁，避免和服务同时写入。阶段锁仍覆盖同一 run 的版本操作；一个数据根同一时刻只运行一轮 Agent 任务，冲突请求明确拒绝，不隐藏排队。

nonce 请求的查询参数必须包含 `stage`、`expected_version` 和 `expected_artifact_sha256`。决定 JSON 必须携带相同三项，加上 `nonce`、`decision`（`approved` / `returned`）；采用含选项的方向时还必须有有效 `selected_option_id`，退回填写 `note`。`approved_override` 与 `override_reason` 仅为历史已保存决定的幂等兼容，不是新决定入口。

这些值取自用户实际阅读的产物，不得提交前偷偷读取最新版替换。服务端只落盘 nonce 摘要；相同 nonce 与相同决定重试幂等，更改选项、理由或决定则拒绝。模型轮次执行中、版本冲突或失效时返回 `409`；必填字段缺失返回 `422`，无效阶段返回 `400`。nonce 不是公网身份验证。

### 素材与观察

素材位于 `runs/<id>/materials/`，可从界面上传或在服务停止时本地放入。按文件名引用，缺文件时明确提示；视频由浏览器预览，不转码。上传检查扩展名、64 MiB 单文件上限和最终路径，拒绝同名覆盖；不直接创建阶段产物或批准，但素材摘要变化会使相关依赖失效。

外部观察可写入运行的 `evidence/observations.json`，须绑定文件名、hash、观察层级、方法、覆盖范围、观察者、日期、发现及限制；格式与校验见 [evidence.py](studio/evidence.py)。没有有效观察时仅记 `existence_only`。模型不能通过工具写入观察以冒充自己看过素材。

## 用量、费用与恢复

每次模型请求（API 或 Codex）先持久化 intent，再追加 settlement；台账按 `call_id` 合并有效记录。传输不自动重试，不完整结束、畸形工具参数或缺最终用量不能记作成功。内容是否成功与用量是否完整分别记录：完整非流式响应的合法输入/输出用量会自动记账，即使内容解析失败也不要求手工核账；断流计数或缺失用量仍保留未知，不补零、不要求用户核账。完整返回 `max_tokens` 时，角色循环可在配置限制内发起单独计费的续写；这与重发中断请求不同。

DeepSeek 与 MiMo 的返回按完整 SSE 事件读取，支持多行数据、保活与单独的用量片段；结束原因和 `[DONE]` 都收到后才交付。接口在 HTTP 200 的响应流内报错仍算失败，不把错误事件当作分析或继续执行工具。异常诊断沿原 `call_id` 记录真实提供方、固定错误类别、字段、片段序号与体积/指纹，保留安全的数字错误码；不保存错误原文、正文、推理或工具参数，也不自动换服务、重下原片或重复调用。仅有一项窄例外：DeepSeek 编剧完整返回的单个完整提交在 EOF 只缺根对象一个 `}` 时，经冻结完整 schema、canonical 与零丢弃校验，可在独立副本追加该字符；原参数只存于原调用的私密不可执行证据，公开保留指纹。中断、截断、内层损坏或证据无法保存均不执行；业务校验拒绝则停止本轮，不自动再调用模型。此处理不等于作品质量通过。中断、超时或停止时保留已收到的合法计数，标为部分用量，不确认最终费用。视频已下载而解析失败时，下一次明确发起的参考任务复用原片。离线测试不能代替真实模型验收。协议依据：[MiMo Chat Completions](https://mimo.mi.com/docs/en-US/api/chat/openai-api)（2026-10-07 核对）。

未知用量或价格保留为未知，美元金额为 `null`，不能补零。已知小计、未知调用和待核实状态分别显示；当前个人工作台不提供手工核账流程，未知用量不阻断任何项目后续调用。实际账单由用户在提供方平台查看，未来商业化积分/计费另行设计。金额是价目表估算，不是提供方账单。

工作台默认不设累计 token 或美元额度。历史 `config.json` 中的数值软阈值仍兼容；若保留数值，会跨该数据根所有运行累计，在调用前检查，最后一笔可能越过阈值。将 `budget_limit_tokens` 和 `budget_limit_usd` 设为 `null` 即关闭旧阈值；台账始终保留。

日常恢复只处理未结束的阶段尝试，不要求用户填写 token 或媒体计费用量。已结束调用即使用量未知，也允许用户明确发起下一轮；未完成的阶段仍可在「制片对话 → 找回创作进度」关闭，保留历史且不自动重试。

以下命令为保留的开发排错/历史兼容入口，不是用户继续创作的前置要求。在应用目录执行，显式指定数据根，不调用模型、不批准内容、不自动重跑。先停止对应服务；只有取得提供方用量或未受理证明才能对账，不得从部分输出猜 token。

```powershell
python -m studio.recovery --data-root <DATA_ROOT> pending
python -m studio.recovery --data-root <DATA_ROOT> reconcile <RUN_ID> <CALL_ID> --input-tokens <N> --output-tokens <N> --evidence-note "提供方用量记录或未受理证明的出处"

# 关闭崩溃遗留的指定开放尝试；不清除原稿、历史或未知费用
python -m studio.recovery --data-root <DATA_ROOT> attempts <RUN_ID>
python -m studio.recovery --data-root <DATA_ROOT> abandon <RUN_ID> <STAGE> --attempt-token <TOKEN_FROM_ATTEMPTS> --reason "中断核查说明" --server-stopped
```

浏览器刷新或关闭不会取消已接受的任务。发送结果不明时页面保留 request_id，点击「确认提交状态」会使用原 ID，不生成第二笔请求。服务重启将未完成任务标为 interrupted，用量未知不要求手工处理，不自动重发；打开原项目即可看到记录和恢复提示。

任一任务运行时，输入框可发送「插入调整」。工作台先在原项目事件日志记录原话、request_id 和选定作品的准确版本；当前调用到达安全检查点后停止后续步骤，再由主制片读取原要求、顺序补充和已保存成果，判断调整时机并建立接续对话轮。界面区分调整已收到、正在结束旧步骤和已接续；刷新可恢复状态。同一指令重试不重复接续。服务中断、原轮留下未完成阶段或连接准备失败时，调整仍保留，但不会擅自重试；处理恢复事项后点击「继续保存的调整」才会建立接续任务。运行中调整暂不携带新附件，图片与视频制作仍走原确认入口；中途消息不自动授权或重提媒体请求。

进度区显示角色的公开行动说明和实际操作。DeepSeek 仅流式展示公开文本，Codex 只采用明确标记为 commentary 的消息；私有推理和未完成工具参数不显示。浏览器用任务事件 SSE 订阅进展，断线时回到轮询。停止对 Codex 发出原生中断请求，对 DeepSeek 流式读取发出本地关闭请求；其他已开始的操作可能仍需等待结算。停止不撤回已完成产物，也不保证撤销当前调用费用；不完整用量保留为未知或部分记录。

恢复后由用户明确要求继续，系统依据当前版本与项目状态执行。仍开放的阶段尝试可在站内关闭，或使用上面的 abandon 命令；未知用量仅作排错记录，不阻断继续。「准备继续创作」只放入可编辑草稿，发送后才启动新一轮。确认模型请求尚未发出的本地配置/握手失败记录为失败、已知零 token，不制造未知账阻断。

## 图片分析与采用

项目素材 → 分析图片 → 选择服务、视觉模型及用途 → 确认一次调用 → 核对结果 → 采用所选观察。上传文件本身不调用模型。已有 MiMo 或 OpenAI/Anthropic 兼容连接可用于图片输入，但具体模型必须支持视觉；DeepSeek和Codex CLI尚未接入此图片入口；视频使用独立声画/抽帧观察入口。支持静态 PNG/JPEG/WebP，原文件沿用上传上限 64 MiB、单边 8000 像素、2000 万总像素；验证真实文件及非动画属性后，大图自动准备最多 4 MiB 的观察副本，优先保留分辨率，透明图保留透明通道。主制片的多图观察按每批 7,000,000 字节自动拆批，成功结果逐批保存；已调用失败不会自动重发。原图与获批制作参考图保持原字节，观察记录同时保留原图与实际发送副本的指纹、尺寸和体积。详细策略见[素材理解与参考迁移](docs/material-understanding.md)。

采用现有 `/api/runs/{run_id}/jobs/{job_id}` 查询与取消；创建入口为 `POST /api/runs/{run_id}/image-analysis`，包含 `request_id`、文件名和 `expected_sha256`、连接 `expected_revision`、`connection_id`、视觉 `model`、`purpose`（product/reference）及显式 `consent: true`。同请求标识与同参数只执行一次，不自动重试、不修改角色配置、不把图片字节或密钥记入事件日志。调用复用 Ledger，未知用量不阻止再次调用；无准确价格时保留金额 null。

`GET /api/runs/{run_id}/image-analysis` 返回可用连接与候选记录。模型结论先保存在原 run 事件日志，未采用前不会进入素材依据；`POST .../image-analysis/{analysis_id}/confirm` 绑定 `expected_candidate_sha256`、`expected_manifest_sha256` 与 `selected_findings` 索引，只将用户所选观察和全部限制追加至既有 `evidence/observations.json`。同一选择重复确认不追加，不同选择及旧图片拒绝；修正通过补充人工观察保留历史。观察不是性能验证或制作批准。

图片输入格式参照 [OpenAI 图片输入文档](https://developers.openai.com/api/docs/guides/images-vision) 与 [Anthropic 视觉文档](https://platform.claude.com/docs/en/build-with-claude/vision)，2026-09-19 核对。离线协议测试验证实际图片块和台账边界，不代表任一真实兼容端点已通过验收。

## 局部修改与版本比较

「创意方向 / 脚本 → 编辑方向或镜头 / 比较版本」可逐个编辑现有方向或镜头。文字暂存在当前浏览器窗口，点击「保存修改草稿」后写入项目既有事件日志；保存不调用模型、不改当前方案、不改变审核或采用。草稿绑定准确原稿版本与指纹，重复保存请求不重复写入，不能套用到已有新版本或依据已变化的方案。

「整理为新版本」会展示对应导演/编剧的当前模型，明确确认后进行一次模型调用，将修改同步至完整正文。卡片由用户修改确定；其他对象、素材绑定、证据和限制保留，主制片自检后交用户决定。新版本不继承旧审核与批准，下游依赖失效；改动时码或时长会将总时长标记为待复核，并增加节奏复核说明。模型调用使用既有任务与台账，不自动重试；取消时若已收到完整返回则保留新版供核对。未知用量不阻断继续。

当前支持修改已有对象字段，不支持增加、删除、重排镜头或改方向编号。历史格式、依据已变化、尚无结构卡片的方案需先由制片团队更新；旧版仍可阅读和比较。「版本比较」显示内容前后值，依据记录和正文差异按需展开，长正文差异有截断提示。

- `GET /api/runs/{run_id}/edits/{stage}?version=0`：读取当前或指定版本、编辑资格、草稿及可比较版本；stage 为 direction/writing。
- `POST .../edits/{stage}`：保存 `request_id`、`expected_version`、`expected_sha256` 与 `edits`（row、field、value）。
- `POST .../edits/{stage}/{draft_id}/generate`：绑定 `request_id`、`expected_draft_sha256`、连接 `expected_revision` 与显式 `consent: true`；查询、取消复用现有 jobs API。
- `GET .../artifacts/{stage}/compare?from_version=1&to_version=2`：只读比较两个完整性校验通过的版本。

以上已通过隔离假模型与界面测试；真实模型对正文与卡片的一致性、创意质量尚未验收，不能以状态机测试代替内容审核。
## 商品资料复用、项目参考与就地反馈

- 「需求整理 → 商品资料」可整理名称、商品信息、证据来源、未知与限制，另存不可变资料卡；「新建项目 → 复用商品资料」先核对再选用。资料卡保留准确来源版本、保存日期及来源限制；新的需求明确标注为未重新核验的历史快照，不复制原方案、素材或批准。仅 US 项目可复用，不替代商品事实源。

接口：`GET /api/product-cards`；`GET/POST /api/runs/{run_id}/product-cards`；新建项目可附 `product_card` 精确绑定；`GET/POST /api/runs/{run_id}/references`；`POST /api/runs/{run_id}/references/{case_id}/remove`。就地反馈复用现有 learning proposals 预览与 apply 接口。
## 模型选择、项目费用与作品表现

模型设置区分文字策划角色与素材区单独发起的图片分析。配置完整度只是当前字段是否齐全，不代表真实调用通过；更换服务提供方会清空受影响角色的旧型号，服务地址变化不沿用旧价格。价格按准确服务与模型显示，保存仅影响后续任务。现有 Codex CLI 登录和 API Key 机制保持不变。

「用量与费用」读取当前项目既有台账，分别显示调用次数、已记录 token、已知美元估算、媒体人民币估算及未知金额次数，可按角色或模型查看，并导出 CSV。金额未知不等于免费，用量未知与价格未知分开；未返回用量仅作提示，不提供手工核账入口。失败/取消仍可能产生费用。历史金额不套用当前价格，不显示提供方剩余额度，不自动获取账单。

「作品与表现」在项目顶部进入，关联已经发布的公开 HTTPS 作品链接与用户明确选择的脚本历史版本，记录实际作品相对稿件的差异。这里只保存本地关联，不访问链接、不发布、不读取平台账户，不代表成片已验收或获得发布授权。

每条表现观察须注明统计开始/结束时间、观察时间、流量来源、数据来源与口径、观察限制；播放、点赞、商品点击、归因订单、美元销售额与广告花费可留空，未知保持 null。单次修正追加新记录，原记录保留；不自动计算跨区间趋势、ROAS 或效果排名。每条记录标记用户报告、未经自动核验。可以将指定记录带到制片对话草稿，核对后再发送复盘；不会自动改写学习库或启动模型。

- `GET /api/runs/{run_id}/outcomes`：可核对的 writing 版本与作品观察历史。
- `POST /api/runs/{run_id}/outcomes`：绑定 `request_id`、`version`、`artifact_sha256`、作品名称、链接、带时区发布时间与实际差异。
- `POST /api/runs/{run_id}/outcomes/{publication_id}/snapshots`：绑定 `request_id`、`expected_latest_id`，保存统计区间、指标及来源。拒绝未来日期、非法数字、旧记录并发覆盖和无法核对的源稿；相同请求幂等。浏览器保存未确认时保留冻结请求，重开后先识别已保存结果。

作品和表现继续使用原 run 的不可变事件记录，不另起采集器或经营数据库；不会回填 Product Intel 或覆盖线路内业务事实源。该作品记录模块不自动采集平台数据或判断经营效果；媒体制作的独立入口见下文。
## 图片与视频制作

同一工作台的「分镜」「成片」承接媒体执行。主制片通过 `read_production` / `prepare_production` 准备并自检实际生成描述；高级面板保留手动编辑。方案保存不调用模型；图审和媒体生成提交仍由用户完成。Codex 图片生成的控制模型取自「视觉策划」角色已保存的 Codex CLI 模型；该角色使用其他服务或型号留空时，使用本机 Codex 默认模型。单张和整组生成的确认卡会显示该模型，设置在确认后变化则需重新核对。画面区可点选某条首帧描述或生成图，在对话中提出定点意见；对话区可一次核对并顺序提交当前未出图的整组首帧，生成后可一次确认展示的准确图片。也可在对话框说「生成全部首帧」或「确认这批生成图」打开同一张整组核对卡；修改意见不会被当作生成授权。整组任务绑定每条草案版本与参考字节，任一条失败即停止后续提交，已完成结果保留；有图片任务结果未知时，整组停在该张，不能跳过它生成后面的图片。用户可凭证确认原任务未提交，或明确保留原结果及费用未知、再单独核对下一轮生成；恢复决定本身不会调用图片工具。对于视频项目，整组图片均确认后，工作台在一次文字任务中按已保存的剪辑计划准备每张图对应的单首帧视频输入；「成片」逐段展示参考图、描述、时长与费用，用户可一次核对并顺序提交未完成的视频段。任何视频提交或取回结果未核实即停止后续段；全部取回后由本地 FFmpeg 按已保存的准确切点截取、复用、叠字并拼接，保存片段与剪辑计划指纹，不产生新的提供方生成费用。顶部制作按钮先打开只读摘要并定位制片对话；对话中的「核对并继续」进入制作详情，媒体生成仍须进入最后费用确认；已保存方案遇到模型能力不可用时，主操作打开模型设置。

1. 主制片依据已经批准的准确脚本准备制作方案；内部保留不可变版本，修改不会覆盖原记录。
2. 主制片核对开场、推进、回报、商品作用和执行条件，修正发现的问题；准确制作输入展示给用户核对。历史审核意见仍可阅读，但不构成新草案的放行门槛。
3. 视频参考图须在大图界面由用户确认。批准绑定原始文件名与 SHA256；换图后旧批准不能沿用，可明确撤回。明确的视频项目在本次图审确认后，系统以图片与当前已确认脚本的 SHA256 和固定请求标识接续已有主制片任务，准备并自检视频输入；未能启动时显示原因和显式继续入口。接续不提交媒体生成，也不授予费用权限。
4. 核对实际 prompt、图、时长、清晰度和费用后，用户勾选同意并启动一个生成任务。保存、打开页面和轮询不触发生成。
5. 输出校验后写入本 run 的 `materials/`，保持原记录、任务与费用。生成成功仅表示文件已保存，实际画面、声音与创意效果仍待验收。

### 镜头身份与整套覆盖

目标镜头清单只来自已采用脚本的 `segments`：六段脚本要六份输入，三段脚本要三份，不由模型指定数量，也不硬编码。历史纯文本稿没有可读的镜头清单时，界面与主制片都如实说明缺口，不猜数量。

每份制作输入带稳定 `shot_id`（`shot-01`、`shot-02`……，由该输入自身的标识派生，与列表位置无关）。同一镜头的修改用 `supersedes` 指向被替换的那一份：旧输入保留可读，但不再是默认生成对象，也不读作新增镜头；没有声明后继时，同一镜头同一脚本下较晚的一份为当前版本。`prepare_production` 接受 `shot_id` 与 `supersedes`；两者都不传时保持原有「一次请求一份输入」的行为，旧项目照常可读。

「分镜」按镜头显示真实阶段——未准备、输入已准备、待授权、已提交、生成中、取回中、失败、结果待核实、已完成——并在该镜展开处直接给出这一次的实际原因与下一步，不需要到技术历史里猜。已经生成但尚未取回与根本没有提交必须能分开：前者只查询原任务，后者才是尚未花钱。被替换的历史输入单列在分镜下，不会和当前输入一起生成。

整套交付检查逐镜核对：`production_input` 要求每个目标镜头都有绑定当前脚本版本与基线的输入；`production_media` 要求每镜都有可阅读的实际结果。一面镜头的草稿不等于整套输入准备完成，一张图片不等于整套分镜完成。主制片与界面读取同一份状态投影（`studio/production.py` 的 `target_shots` / `coverage` / `_read_state_without_service`），因此「第 3 镜为什么没出来」在界面与对话里是同一个答案。`read_production` 是免费只读，返回该投影的脱敏版本：不含 nonce、素材 URL、凭据与提供方响应，`endpoint` 只保留主机名。

准备失败按原因区分并在记录里给出 `code`、`message`、`target`、`retryable`、`next_action`、`needs_user_decision`：脚本版本已变化、脚本尚未采用、上游依据变化、遗留阶段尝试、参考图不可用、参数缺失各有自己的说法，不再统一要求用户「核对参数」。未分类的失败按不可重试处理——重提一次可能已经到达提供方的提交，就是付两次钱。

当前图片使用本机 Codex CLI 原生图片工具及其现有登录。独立临时线程只允许图片工具，参考图冻结后以像素输入；不复用开发对话或文字角色适配器。已核实本机协议可用；一次真实整组提交在首张返回结果未知，未取得图片，故尚未完成真实出图验收。原生协议不提供图片计费用量，也不能硬性保证工具只调用一次；发现额外调用会停止本地等待，保留可验证的部分输出和未知用量。图片已保存即可继续图审；未返回计费用量不会阻止下一次调用。不会把文件张数当收费量、把订阅折算成免费或杜撰余额。CLI 自身可能保留 generated_images 缓存；工作台只读取返回的图片字节，不按回执任意路径读文件。

视频复用原 Windows 用户已有的百炼 DPAPI 凭据，仅在明确提交或查询原任务时解密，不修改实际配置、不复制凭据。当前接入北京 `wan3.0-video` 单首帧方式：2–30 秒、480P/720P/1080P，跟随参考图比例、原生声音开启、关闭自动 prompt 扩写；参数随方案冻结。发送原始参考图 data URL，视频参考需满足提供方至少 240 像素、最大边 8000、比例不超过 8、最多 20 MB 的条件。工作台图审允许静态 PNG/JPEG/WebP，最多 24 MB / 4000 万像素，不能静默压缩已批准图片以凑接口要求。

百炼北京地域公开原价估算按 ¥0.3 / ¥0.6 / ¥1.2 每秒分别计算；2026-09-29 核对，来源 [官方 Wan 3.0](https://help.aliyun.com/zh/model-studio/wan3-0-video)。实际优惠与账单未核验。视频人民币估算单独显示，不与文字美元金额相加；当前工作台不设累计额度。媒体调用写入同一 `ledger.jsonl`：`usage_unit=images|video_seconds`、`usage_quantity`、`estimated_cny`；文字 Tokens 不凭空补 0。未知媒体用量仅保留记录，不阻止新的模型调用；查询和取回原任务不重发生成。

恢复语义：request_id 保证原请求重试不重提交。百炼接受后立即保留 task_id 和固定 workspace endpoint；下载失败或服务重启后从原任务查询，不能自动换空间或再次提交。提交超时且没有 task_id 时，用户凭提供方证据补充任务编号，或明确登记未提交；已有任务/输出不能记作未提交。Codex 图片调用结果未知且无可查询的原任务时，用户可决定承担旧请求结果及费用仍未知的风险，然后另行确认一次新的生成；系统不自动重试，也不把旧用量记成零。图片计量或视频秒数仅记录提供方返回值，缺失不要求用户手工核账。关闭制作对话框只停止页面轮询；停止制作执行仅结束本地等待，远端仍可能生成并计费。

制作基线：首份方案必须来自完整且批准的当前 writing。之后同一制作基线可接收本流程生成的派生媒体，不让每次输出迫使脚本重写；原素材、观察、脚本、上游版本、方向选择、参考选择或审批变化仍使该基线失效。创作板的原有素材依赖机制不被放宽。新基线仍需要更新稿件并明确批准。

接口位于 `/api/runs/{run_id}/production`：GET 读取能力、方案、分镜顺序、剪辑计划、素材与状态；POST `/drafts` 免费保存；`/edit-plan` 保存绑定当前已确认脚本和首帧方案的切点、声轨来源、字卡与商品规格；`/material-approvals` 和 `/material-approvals/batch` 为浏览器图片决策，`/material-approvals/continue` 与 `/material-approvals/batch/continue` 为已确认图的显式准备恢复；`/{draft_id}/review` 已停用；`/{draft_id}/generate` 与 `/batch-generate` 明确生成；`/assemble` 按准确剪辑计划截取、复用、叠字并拼接已取回的视频段；`/attempts/{attempt_id}/refresh` 查询原视频任务；`/attempts/{attempt_id}/recover` 核实原任务或记录承担图片未知结果后另行重试的决定。未知计费用量不要求手工补齐。浏览器专属确认 nonce 不进入模型上下文。首张真实图片任务没有返回可保存图片，不能以 mock 返回宣称提供方出图或质量通过。
## 显式接续旧案例

已有已采用脚本的旧项目若缺少共同制作设计，可在制作页打开「补齐制作设计，保留原脚本」。确认一次素材角色模型调用后先预览人物、场景及原镜头绑定；核对后保存素材计划和脚本新版本，再从原脚本入口采用。原方向、脚本原文和旧图片保留；旧图片不会自动取得新版批准，也不会自动生成媒体。尚未确认的原图片任务优先核实，不能通过补设计或换输入跳过它。具体边界见[开发契约](docs/development-contracts.md#本地整合后的制作边界2026-10-07)。

项目顶部「项目历史」读取迁入的准确原文、未采用草稿、用户反馈、历史批准及费用说明。主制片使用 `read_project_history` 按登记 ID 读取相关文本；独立审核角色不读取旧生产者对话。历史原件只作资料，不带执行权限。

本地管理员可用 `python -m studio.history_import --plan <PLAN_JSON> --data-root <DATA_ROOT>` 校验明确计划，加 `--apply` 才执行。计划要求 US 线路、全新 run_id、接档 brief/intake/summary、历史费用边界、明确来源目录（可附 files 精确白名单）、精选文本及已核对 hash 的图片/视频。没有任意文件导入的 HTTP 入口。

应用时必须停止同数据根的服务；单 writer 锁拒绝在线并写。完整原件复制到独立暂存、校验 hash，最后才将完成项目发布到 runs；失败暂存保留供核查，目标已存在时拒绝覆盖。原 Backlot 不改写，旧脚本不执行。只有精选 md/txt/json 通过只读接口返回，原始 HTML、脚本、日志和提供方签名 URL 不作为站内页面或模型历史提供。商家源素材与历史生成素材分别标注；未重做视觉观察。

迁移仅建立接档 intake 和 pause 路由，不迁入有效审批、当前生成任务或费用台账，不创建模型对话、不调用模型。用户在站内明确继续后再选择 continue/edit；新执行仍受本站图审、费用和版本限制。本站调用费用与历史费用说明分开保留，未知实际金额不补零。
