# us-video-studio 目录约定

本文件只约束本应用。跨项目规则见仓库根 [AGENTS.md](../../AGENTS.md) 与
适用的全局规则，线路事实源见 [tracks/us](../../tracks/us/README.md)。

## 定位

US 视频与图文策划、受控图片/视频制作的本地独立工作台。站内主 Agent 调配角色，审核 Agent 独立审核；Codex CLI 或用户配置的 API 作为模型连接。**业务运行不依赖当前 Codex 开发对话**，与 [Backlot](../video-workbench/README.md) 分别维护运行状态。

线路归属：**仅 US**。本应用不承载 SEA 任何结论，SEA 不得引用本应用的运行数据。

## 什么放哪

| 路径 | 放什么 | 不放什么 |
| --- | --- | --- |
| `studio/` | 应用代码。领域层（`models`/`store`/`pipeline`/`ledger`）与 Agent 层（`agents/`）、工具层（`tools/`）、HTTP 组合入口（`server.py`）和分域路由（`http_*.py`）分开 | 真实运行数据 |
| `studio/web/` | 原生 HTML/JS/CSS 前端，不引前端框架 | 构建产物 |
| `<app>/scripts/` | 本应用启动与开发工具：`start.ps1` 做诊断后启动，`seed_preview.py` 造假数据预演界面。**注意与仓库根的 `scripts/` 是两个目录**，后者放共用业务脚本 | 业务脚本 |
| `tests/` | 离线测试。**默认全部不联网**，用假模型覆盖循环与状态机 | 需要真实 API 的用例 |
| `README.md` | 定位、启动、运行契约、恢复命令与两套工作台的关系 | 逐次运行记录 |
| `requirements-local.txt` | 本机额外依赖及版本 | 全量生产依赖 |

真实运行数据必须在仓库外，以服务的 `STUDIO_DATA_ROOT` 为准；未设置时的历史默认值为 `J:/E-Business-Video-Data/us-video-studio/`。不要把默认值当作当前机器已使用的数据根；实际启动与恢复入口见 README。
素材（图片与视频）属于运行数据，同样不进 Git。
代码与非敏感配置示例进 Git，实际连接配置、凭据与运行数据不进 Git。这与 `apps/video-workbench` 的既有做法一致。

## 命名

- 阶段名用 `snake_case`：`intake` / `direction` / `material_plan` / `writing`。
- 角色名用 `snake_case`：`orchestrator` / `director` / `material` / `writer` / `reviewer`。
- 运行目录 `runs/<run-id>/`，`run-id` 用 `[a-z0-9][a-z0-9-]*`。
- 素材放在 `runs/<run-id>/materials/`，**文件名保持磁盘上的原样**——产物里的
  `file` 字段就是靠这个文件名找到它的。中文名、空格、大小写都允许；
  路径分隔符不允许，见红线 7。
- 产物文件名由阶段决定：`<stage>-v<n>.md`，版本号只增不减。
- 测试文件 Python 用 `tests/test_<模块>.py`，前端渲染器用 `tests/js/test_<模块>.mjs`。

## 什么时候清理

- `runs/` 下的运行数据**只标记不删除**。过期靠状态与 `history/` 表达，不靠删文件。
- 用户可从项目卡片或工作台删除项目，删除前展示项目名和影响；删除写入原事件日志并移入界面回收站，不移动或清除运行目录。回收站可恢复原项目，保留素材、对话、版本与调用记录；删除状态下禁止继续调用模型或生成。正在执行的项目须先停止并等待任务结束，删除不得暗中取消任务。台账汇总继续包含已删除项目。
- 产物不可变。修订产生新版本，旧版本留在原地。
- 本目录内不留临时文件；需要暂存写到系统临时目录。

## 命令

安装、显式选择数据根、启动及 Python/Node 离线测试命令统一维护在 [README 的启动与检查](README.md#启动与检查)。不要复制旧机器的盘符启动另一个空数据根；更新前核对监听进程与活动任务，静态文件刷新不能证明后端已加载。

展示函数优先保持可在 Node 中独立测试；页面控制器可使用 DOM。`blocks.js` / `md.js` 的转义与渲染不依赖浏览器或 jsdom，修改后必须运行 README 中的 Node 测试命令。

## 编码

**仓库根**的 `scripts/quality-gate.ps1` 强制：**人类可读文件（`.md`/`.csv`）用 UTF-8 带
BOM**，**代码与配置（`.py`/`.json`/`.yaml`）用 UTF-8 不带 BOM**。加 BOM 是为了 Windows 下
中文不乱码。新建或改写 Markdown 后跑一次**仓库根**的 `scripts/validate_text_encoding.py`
确认。（本目录下也有一个 `scripts/`，放的是本应用的开发工具，不是这两个脚本。）

## 本应用红线

1. **生成仅由用户在制作界面明确提交。** 图片走 Codex CLI，视频走百炼单首帧链路；Agent 可准备方案但不得批准图片、授权费用或提交生成。准确输入须先完成制作检查；视频只接收本站按图片字节指纹获批的参考图。真实生成的验收费用另行确认，离线测试不联网、不花钱。
2. **审批只能来自用户在界面的点击。** 任何 Agent 工具都不能写入 `approval`。
   审核 Agent 可记录审核意见，但不能代替用户批准。
3. **两套工作台分别维护，互不写入运行状态。** Codex 驱动的 `apps/video-workbench`
   保留原记录，独立 Studio 需独立验收；显式迁移只读原件，不自动迁移历史批准。
4. **不把技术成功当内容成立。** 渲染成功、字段非空、哈希校验通过都不等于内容可用。
5. **费用台账记全。** 调用先记 intent，再记 settlement；未知用量或金额不得补零。
   Jeffery 于 2026-09-21 明确：当前为个人工作台，不需要手工核账功能。未知用量仅保留排错记录，不阻断后续调用，不要求用户填写 token/费用；账单以提供方平台为准。当前不设工作台全局 token 或美元额度；历史用量照常记录，金额只是估算。显式配置的旧数值上限仍兼容。
   内容失败与用量状态分别记录：完整非流式响应已返回合法输入/输出计数时自动记账，正文或工具参数解析失败不使该用量变成未知；流式中断的部分计数仍保留未知，不补零、不阻断。
6. **改规范先改本文档，再改代码。**
7. **素材只往 `runs/<id>/materials/` 落，且只能是图片与视频。** 上传不直接创建阶段
   产物或批准；素材字节与观察摘要变化必须使相关依赖失效。落地前检查扩展名白名单、
   单文件大小上限、解析后路径位于素材目录内；保留合法文件名，拒绝同名覆盖。
   失效判定用**事件世代（generation）单调前进**，不依赖内容哈希回等：产物写入时冻结
   当前证据/参考世代，世代前进即永久 stale；即使内容回到历史哈希（A→B→A）也不得使
   旧批准复活。素材上传须写入 `material_uploaded` 事件以推进证据世代。
   推进世代与改变证据指纹的只有**源事实**（素材上传/导入、观察、非自主的创作模式选择）；
   本 run 自己生成的产物是派生物：出片时它会同时写入 `material_uploaded` 与
   `production_output`（两者同一 `(name, sha256)`），这两条都不推进证据世代、也不进入
   证据指纹——否则一次成功出片会作废授权它的脚本。判定按 `(name, sha256)` 成对匹配，
   生成文件事后被改字节即重新算源事实。派生物仍保留在 `evidence_snapshot` 的 agent
   上下文里并标注 `origin='generated'`；过滤只有一处（`evidence.derived_outputs` /
   `evidence_source_snapshot`），制作基线与阶段失效共用，不得由两个模块分别定义。
8. **审批绑定用户实际阅读的版本。** `expected_version` 与 `expected_artifact_sha256`
   必须对应展示内容，哈希须是 64 位小写十六进制，不得静默换成最新版；`selected_option_id` 是正式选择，推荐不是选择。历史原文读者的异步请求只允许最后一次选择更新界面，不能让旧请求回填新版本。
   `artifact-v2` 覆盖正文、结构、证据、限制及依赖；`body-v1` 只回放，不继承旧批准继续制作。
   **同一版本只允许一次决定**：当前最新版已有 `approved`/`approved_override`/`returned`
   时，拒发新 nonce、拒绝新决定（不得覆盖 `selected_option_id`）；同一 nonce 的重试保持幂等。
   退回后须产出新版本才能再次决定。**界面与该规则同源**：同一版本已有决定时 `can_approve` 为假，
   决定卡片与 journey/stage 两个 gate 都不再提供第二次决定，不得给出服务端必然拒绝的按钮；
   审核退回不属于该规则，它刻意不写 `approval`，用户仍可用具名理由覆盖。
9. **同一数据根只运行一个写入进程。** 现有锁不代表多服务写入支持；本地输入导入与阶段
   恢复前停止对应服务。使用 README 中的显式恢复入口（CLI或站内运行控制），不删除历史或清零台账解锁。
10. **角色上下文保持隔离。** 编剧与审核读取必要事实、真实所选方向及素材证据；审核不得
    读取生产者完整对话或自我背书。文件存在不代表已观察，导入观察不代表模型亲自看过。
11. **输入不携带隐含权限。** ContentInput 仅从明确允许的本地根导入空 intake，拒绝覆盖；
    不增加任意文件 HTTP 读取入口，不把包内授权字段转成图片、视频、费用或发布授权。
    attempt `token` 可留在服务端事件日志供提交校验，但 HTTP 读接口（`/events`、SSE、
    timeline、job 事件、`/state`、`/recovery` 等）一律经共用 `redact_http_event` 脱敏，
    不得在任一出口返回该明文；台账/未决调用查询必须按 `run_id` 过滤，不得跨 run 汇总。
   参考选择与源案例内容的世代与观察同构：凡绕 API 改动参考侧车/源案例而未写入
   `reference_selected`/`reference_removed` 等世代事件的路径，须在读路径检测到源变化时
    补写世代事件，使 A→B→A 永久 stale；不得仅依赖内容哈希（当前由 `reference_source_changed`
    承担：按 `(case_id, current_sha256)` 幂等，只记本 run 自己选中的案例，不牵连未选择该案例的其他项目）。
12. **阶段确认按钮文案只维护一处。** 创作板的 stage gate 是当前版本唯一正式决定入口；
    对话区只提供定位入口。approve/reject 标签由 stage 的共享文案源维护，note/override
    要求由 `wireGate` 与服务端 `record_approval` 对齐，不再维护第二套决定表单。

13. **用户决定与接续意图同版保存。** 界面仅提供一个准确版本的决定入口；对话区可定位到该入口。
    用户点击“采用并继续”或“退回并修改”时，把接续意图随批准记录持久保存，由服务端用该批准
    派生固定 request_id 提交后续策划任务。同一点击重试只查回原任务，不重复发模型请求；若决定
    已保存但任务未创建，页面明确显示待接续并允许用户点击重试。服务重启不得自动重发已创建的
    任务。该意图只覆盖后续文字策划和制作输入准备，绝不批准图片、费用或视频生成。

14. **运行诊断不得改写业务状态。** 启动前 doctor 只检查所选解释器、依赖、明确数据根、
    writer 锁、监听端口和本机媒体工具；不创建新数据根、不读取凭据明文、不测试付费模型。
    站内诊断只显示本进程启动时冻结的代码指纹、启动时间、数据根标识和依赖状态，
    不能把“已配置”写成“真实模型已验证”。

15. **Skill 依赖通过受控方法包读取。** Agent 可见目录与 `read_method_document` 使用同一白名单；
    方法卡只放可执行的稳定规则，标明来源文件与适用角色。历史案例、用户反馈、研究比较与
    holdout 答案继续走原资格过滤和人工审计入口，不因 Skill 相对链接而整篇开放。
    包级检查须验证登记文件存在、角色权限和工具映射，不授予新的生成、审批或费用权限。

16. **Codex 模型选择来自本机目录。** 角色配置可只读调用本机 Codex app-server 的
    `model/list` 展示该登录与客户端返回的可见模型；不硬编码可用型号，不把列表读取说成模型
    调用或额度验证。空值仍表示沿用本机默认模型；已保存但暂不在列表的模型保持原值，须由
    用户主动改选。列表读取不读取或回显凭据，不改角色设置；保存后仅影响下一轮冻结的连接快照。

17. **创作者界面按作品、目标与下一动作组织。** 项目默认只保留一套成果导航；标题在项目
    选择器、实时状态在任务状态行、下一动作是工作区顶栏的单个中性入口——**不设常驻状态
    横幅**，状态与结论以对话流为唯一主轴（与成熟开源对话工作台一致）。内部阶段、完整
    Prompt、尝试记录、ZIP、模型配置和诊断按需打开。图文和只分析项目不得默认显示视频成片占位。方向选择在展示该准确版本的
    方案卡片内完成，仍复用唯一的版本绑定决定、nonce、用户意见与接续机制，不新增批准路径。
    方向方案的短创意标题是可选正式结构字段；旧稿无标题时按原主张或原文阅读，不补写旧字节或
    迁移批准。已采用的方向只从绑定当前准确版本的审批记录读取，不从推荐文字推断。
    选中作品文字后发反馈须绑定当前 run、阶段、版本及指纹；来源变化时不能悄悄把旧选择施加
    到新版。图片/视频优先展示真实可用媒体，再提供制作输入与历史记录；没有媒体不称已完成。
    生成前的准确参考、范围、费用及必要限制保持显见，结果不明只查询原任务。
    脚本默认按已有画面、动作、声音与台词阅读，不能把空台词推断为刻意静音，也不能把已有画面
    藏成逐段技术详情。普通制作修改绑定准确草案及本次尝试交给原主制片，手工 Prompt 编辑只在
    高级入口。最近失败或结果不明只描述本次尝试；上一份仍可核对的生成结果继续作为可阅读作品，
    标为上一份已生成结果，不推断为已采用，也不继承其图审或生成授权。
    视频旁的发布文案必须与实际播放结果所用脚本的版本和指纹配对；旧稿没有独立文案时说明缺口，
    新稿文案须单列并标明尚未对应当前视频。已有明确制作检查意见或失败尝试时，可一键绑定准确草案
    与尝试交给原团队诊断并提出修正；自由描述问题仍可用。诊断不提交媒体生成、不沿用历史授权，
    结果不明仍只核实原任务。
    视频项目的准确参考图获用户确认后，原团队可在同一已批准创作范围内接续准备和文字检查视频
    输入；只针对获批图片及当前已采用脚本，复用原任务幂等机制，失败时保留显式恢复。生成始终停在
    准确输入、范围与费用的用户确认处，图审不构成生成授权；只读打开项目不能启动准备任务。

18. **产品目标只经 ActiveBrief 显式修订，不经采用绕过。** 意图编译为 `studio/active_brief.py`
    的有效简报（intake + 已确认问答 + 已批准修订）。**目标授权来源与 intake 改写权限分开**：
    `goal.primary` 只来自 `run.brief`（建项目时的用户原话，之后不再改写）或已批准 amendment，
    绝不取最新 intake；intake 可自由重写事实与硬约束，它自己的交付形态读法只作为
    `authority=intake_proposal` 条款可见，不改变有效目标。非 intake 阶段 attempt 写入
    `inputs["brief:snapshot"]`，指纹变化使**已带该 key** 的产物 stale（无 key 的旧版不批量作废）。
    direction 各 option 用 `satisfies`/`violates`/`amend_*` 声明条款；**带 `brief:snapshot`
    的产物必须声明**（`bound=True`）：未声明的 option 记 `unmapped` blocker，引用当前简报中不存在的
    clause id 记 `unknown_clause`，**没有声明满足 `goal.primary` 且未对它提修订的 option 记
    `goal_uncovered`**。**准入按每个 option 独立计算**（`brief_gate.options[].admissible`，
    审批用同一个 `gate_blockers_for`）：推荐只决定卡片排前哪个，既不豁免备选、也不因自己被挡而
    取消合规备选的采用入口；只有**所有** option 都不可采用时整阶段才改出简报修订卡。
    不带该 key 的旧稿只报 `unmapped`、不加 blocker、不批量作废。**无 override 硬过路径**。
    改 `goal.primary` 只能 `POST /brief-amendment`：`add` 按新身份校验正文不重复，`replace`/`retire`
    要求目标存在且正文确有不同——诊断文字与 clause id 都不是修订正文，不得兜底成 `replace.text`。
    每条改动记录决定时的原条款正文（`base_text`）与 `expected_brief_fingerprint`：前者让模型改写
    intake 后仍能重新对齐（按 id → 用户批准正文 → 原条款正文），找不到对齐目标时**保留用户批准的
    正文并记 `conflicts`**（不得静默丢弃、也不得拿模型新写的正文冒充已批准）；后者不一致返回 409，
    不静默换基线。**一次提交只记一条修订，一个身份只代表一份不可变负载**：`request_id` 由调用方给出
    并随重试复用——页面按 run+条款保存**完整提交记录**（request_id、原始规范化负载、所属项目与未决
    状态，应答后清除）；同一决定的重试复用原 id 与原负载，新的明确决定换新 id，未决旧记录保留核实
    入口、不被新提案覆盖或顶替身份。服务端在重试解析处比较**冻结的规范化负载指纹**（changes、note、
    approve、声明的方向版本/SHA 与 brief 基线；不含服务器生成的时间与 amendment id）：同 id 同负载
    返回已记录的那条，不顺带写第二条、也不因它自己刚改过简报而返回 409，其 redo 按 amendment id
    幂等解析；同 id 不同负载返回 409 `request_conflict`——不写入、不生成任务、不拿旧成功冒充新决定。
    命中旧记录后的行为取决于该记录的真实状态，pending/rejected 不因重试带上 `approve=true` 就获得
    已批准行为。旧记录缺少冻结指纹时只比较其实际保存的字段（changes/note），不伪造历史声称基线已
    核验。查重、比较与首次写入同在既有锁内完成，同一新 id 的并发提交只产生一个结果。不带 id 时该
    路由不保证幂等——同一用户间隔一段时间做两次相同修订在服务端无法区分，只有调用方知道是不是重试，
    **不得按正文去重**。
    **重放的是整段批准历史，冲突不是只增不减**：后续修订沿正文血缘消解先前遗留的
    冲突与它恢复的旧条款——用户已用更新的决定取代或退休该要求时，旧冲突随之消退；只有真实未决的
    分歧继续阻断。同一条要求连续改两次、intake 已含最新版时，不得再冒出旧冲突或旧条款。
    批准后按 amendment id 派生固定 request identity 启动一次重做
    （`POST /brief-amendment/{id}/redo` 是显式恢复入口）；「已保存但未启动」在 timeline 的
    `pending_brief_redo` 显示，只对**最新一条**已批准修订、且当前简报尚无合规方向稿时成立；
    重试只解析原任务、不重复开任务，也不提交任何媒体生成。
    **每个消费者都读同一个准入结果**：结构化方向卡（`directionWorkHtml` 的 inline gate）与通用
    回退表单共用 per-option 禁用、原因展示、修订入口与 `data-brief-fp`；保存失败后恢复控件时只
    恢复自己禁用过的，不得把业务禁用的选项一律启用。
    对话输入**按每次提交与项目归还草稿**：一次提交捕获原 runId 与输入版本，只有同项目且期间
    没有更新的输入时才放回；`runtime` 的 `submitSteer` 不得自行写输入框，只返回事实（含
    `rejected_text`）。**结果未知不等于被拒绝**：请求发出前写入按 run 的待确认标记——普通新任务为
    `studio-job-pending`、运行中调整为 `studio-steer-pending`，两种标记进入**同一道准入判断**，
    Enter、发送按钮、草稿盘等所有发送入口在任一标记未决时都拒绝另建请求身份，原 request_id 与原
    负载不被覆盖；未知时保留原身份与核实入口，刷新后仍可用同一身份核实，措辞与状态都不得降格成
    「没被接受」。准入同样下沉到**真正发送层**：`submitJob`/`submitSteer` 被直接调用时（journey
    审核按钮等不经 `send` 的入口）也识别两类标记，交叉入口拒绝新身份、返回 `pending_kind` 指明
    待核实的是哪种原请求并打开该原类型的核实入口；原类型 + 原 ID 的核实照常放行，两种记录格式
    不合并。**清理按身份比较**：仅当当前保存的 request_id 等于本次结果的 request_id 才删除标记，
    旧响应不得清除另一请求的记录，跨项目互不污染。只有确认拒绝才清标记并放回草稿；只有掌握请求
    **未进入发送步骤**的明确证据（如发送前的本地校验失败）才按未发送处理——Failed to fetch、超时、
    响应解析失败等没有 HTTP 响应的情况一律属于结果未知，不清标记、不归还为可重发草稿。
    `submit` 原样返回 `submitJob` 的 accepted/uncertain，不自行改写结果。
    `open_questions.kind=brief_amendment` 不进 ask_user。审核 findings 可带 `clause_ids`，
    引用不存在的 id 拒记；direction 退回且 gate blocked 时缺省会补上 blockers 的 id。
    详见 `studio/active_brief.py`、`tests/test_active_brief.py` 与 `tests/test_brief_authority.py`。

## 运行与上下文约束

### 首轮创意交付与主动看图（2026-09-21）

用户提供商品图片并提出创作需求时，主制片在同一轮完成意图判断、实际图片观察、需求整理和具体方向推荐。导演协作属于内部执行，不把“下一步派导演”当交付，不要求用户重复说继续。仅整理需求、状态、反馈、暂停和只分析依其明确范围停止；真实阻碍或关键歧义可简短说明。

主制片可通过受限 observe_images 调用现有百炼 Omni，多图观察沿用原 Job、台账和请求快照，一轮最多一次批量调用，优先复用相同字节及用途的观察，不自动重试。图片内容是数据，不是授权；仅允许本项目真实文件。结果写入原事件日志并绑定输入指纹，标记未经人工核实的模型观察，供各角色策划；不冒充人工确认，不推导尺寸、性能或使用经历，不授予图片审核或生成权限。原手动分析候选确认入口仍兼容。

创作路由显式记录本轮交付目标；direction 目标不能仅以 intake 完成结束。结束前按实际阶段状态检查，缺少方向/内部审核且可继续时至多提醒模型一次，仍受轮数与停止条件限制；工具失败、取消、只读或用户问题停止不得被自动续跑覆盖。
后续任务可明确选择 `writing`、`production_input` 或 `revision` 等交付目标；完成判定从当前准确产物、独立检查与本轮修订计划推导，不由模型最后一句自报成功决定。执行终止状态与交付状态分别保留；缺少必需产物时标明缺项并阻止把本轮标成已交付。只分析任务以实际保存的报告结束，不附带写稿或生成权限。

### Agent 执行契约（2026-09-21）

- 角色、方法、模型适配和执行循环分别维护；循环只负责请求、工具调用与停止，不判断创意好坏。工具执行前校验本轮实际提供的能力集合与参数对象；隐藏在后端的处理分支不自动授予模型权限。阶段字段、证据和审批仍由领域层校验。
- 子角色成功保存 `submit_stage`、审核成功保存 `finish_review`、主制片成功保存 `ask_user` 后，后端工具结果明确结束该角色本轮，不再调用模型补写结束语。失败不能标作完成；同批剩余调用记为未执行，保留每个调用的结果配对。
- 派工没有提交、审核没有结论必须返回失败结果；审核退回属于已完成的审核，不能当作技术失败重试。审核已有结论时读取既有结论，不重复调用模型。
- 角色摘要来自已保存的产物、审核和问题，主制片负责对用户作最终说明。上述改变不增加 Agent 的审批、图审、费用或媒体生成权限。
- 每条新对话先以未选择工作范围开始；上一轮路由只供参考，初始 system 不把旧交付格式写成本轮定论。主制片用 `prepare_creative_context` 为本轮明确选择后才能写稿、派工或送审；本轮已选 status/pause/feedback 后不能自行升级为制作。路由是模型对用户意思的解释，不是新的审批或费用授权，不按关键词自动判断。
- 专业角色修订时能读取本任务开始时的自己上一版产物与指向该版的责任审核问题；只能读自己的目标阶段及原上游，不能读其他角色对话。独立审核仍不读取旧审核结论或生产者对话。
- `read_capabilities` 提供实际工具、冻结模型路由、观察覆盖及制作能力边界；可配置协议不等于模型已通过视觉验收。注册方法可由专业角色按需读取，原始研究/holdout 仍不对模型开放。主制片可分页找回本 run 的历史对话，历史内容不自动产生执行权限。
- 每次 `BudgetedClient` 调用在模型前保存不可变逻辑请求快照，绑定原 call_id、角色、system/messages/tools 与路由；仅放在原 run 的 Git 外目录，事件只保存指纹和引用，不保存认证对象。快照失败则不发模型请求；快照存在不证明网络已发送，实际提供方状态仍看原台账。提供方协议转换后的 wire 请求不在此快照保证范围内。
- 执行中的对话纠偏是新的用户指令：先在原 run 事件日志持久记录原话、幂等标识和目标任务，再请求旧轮停止；旧轮结算后由同一单写入进程接续新对话轮，重新选择本轮范围。收到指令不等于已执行；前端须区分收到、等待旧轮结束、已接续与无法接续。服务重启不自动重发纠偏或模型请求。原任务及新指令不授予审批、图审、费用或媒体生成权限。
- 公开进度只展示模型主动给用户的简短工作说明和后端已经发生的操作；`reasoning_content`、原始推理增量和未完成工具参数不得进入 HTTP 进度。模型返回后、工具调用前及最终答复入库前必须再检查停止状态，旧轮迟到的答复不得作为有效聊天结果。已实际完成的外部操作和真实用量保留原记录，不因停止伪造撤销。

架构依据、当前缺口与分期设计见 [Agent 架构审查](docs/agent-harness-review.md)。

### 按问题执行与局部修订契约（2026-09-21）

- 主制片从原 Pipeline 派生工作顺序，区分保留、更新、内部审核、用户决定和恢复；已有有效上游不因修改下游而重写。证据变化仍按现有完整指纹保守失效，不把字段未改当作批准可继承，不另建任务状态库。
- 对话 edit 路由修改已有阶段前，须在本轮用 plan_revision 绑定准确版本/hash、本轮原话和 local/rework 范围。local 明确允许修改的结构字符串字段，由程序检查路径；同轮不能扩大 local 范围、改写其他阶段或用全文提交绕过。计划是内部执行范围，不是用户批准或媒体费用授权。
- local 仅支持正文由结构生成、依据有效的版本；角色只提交字段补丁，后端保留其他字段、顺序、证据与限制，重新生成正文。旧双写稿或依据过期明确返回原因，不静默转为全文重写。时码/时长修改自动标明全片时长待复核；台词、画面、声音改变须在内部审核复查衔接和声画，不以局部字段校验替代内容审核。
- 新版仍走原 attempt/submit/review，旧稿不可变、旧批准不迁移。计划在模型调用前及提交前检查版本和输入；取消、冲突、无有效补丁不产生新版本。工具范围仅为本轮，后续消息重新判断。
- rework 允许责任角色按新证据更新完整阶段，仍提供准确旧稿、差异来源和已选方向；这不等于许可自动重跑整个流程。下游根据当前依赖与审批逐步处理，不自动提交生成。

### 素材理解与参考迁移契约（2026-09-21）

- 百炼北京 Omni 声画观察使用单独的原生适配器，显式素材分析时复用本机 Wan 加密凭据与北京业务空间，不修改创作团队路由。提交前冻结所展示的业务空间、模型、价格和素材字节；不读取其他服务密钥。普通兼容连接仍为原抽帧能力。
- Omni 输入为带原音轨的视频文件，最长 90 秒；本地检查并在需要时生成有界 MP4 观察副本，绑定原件和实际输入的指纹与时间范围。提供方采样不等于逐帧验收；无音轨、音轨部分覆盖及无法判断的时段必须明确保留。结果按时间段保存，用户选择后才进入创作证据，不能自动批准成片。
- Omni 沿用 JobManager、逻辑请求快照与 token 台账，人民币单价及估算单独记录，不换算或冒充美元。中断、拒绝、格式错误不自动重试；未知用量不能写成零。只读页面不解密凭据或调用模型。

- 普通兼容连接的视频画面分析沿用单次显式素材分析、冻结连接、原 JobManager/Ledger 和逐条采用机制，不增加 Agent 媒体调用或采用权限。视频限原上传上限 64 MiB、90 秒，解码最多抽取 12 帧并缩小到最长边 768 像素；原件保留。使用 PyAV 在本地解码，不上传原视频、不执行素材脚本、不请求外部地址。
- 每帧绑定原视频字节指纹、帧 ID、原时间戳及实际 JPEG 输入指纹。分析只允许引用实际输入的帧 ID。必须注明稀疏抽帧、未发送音频、帧间动作与声画配合未经验证；检测到音轨不代表听过声音。解析失败、取消或缺少解码依赖时不自动重试。
- 参考分析分开保存可见观察与机制假设；机制条目必须引用实际观察，并说明不可迁移因素和下次验证改变。只有用户采用的观察及引用全部已采用观察的机制才进入当前证据；参考主张和生成素材不得成为本款商品事实。
- 创作前上下文按商品观察、参考方法、观察缺口组织，并把未观察、仅转写、仅抽帧等范围交给导演、编剧和独立审核。该视图从原证据派生，不建立新事实源，不将缺少资料一律变成禁止创作或用户作业。
- 离线评估使用固定合成素材与场景，覆盖原图/视频像素实际入模、时间引用、采用隔离、参考事实隔离和上下游输入。真实模型对画面、声音与创意的理解质量仍需另行实际验收，不用假模型通过率替代。

- 2026-09-22 用户明确：这类调用与费用是**后台数据**，不进入创作交互——既不打扰，也不用"已花费 X"之类的便条替代。开发者复核走既有「用量与费用」（含百炼人民币单独区块、逐次明细与 CSV 导出），不新增面向创作者的展示；面向用户的计费呈现待商业化时另行设计。这不妨碍主制片按需调用、台账如实记账。
- 主制片与专业团队共用自主创作、指定参考复刻、局部借鉴的明确上下文；本轮操作权限仍独立判断。指定参考绑定实际文件和分析版本，切换模式保留旧稿并使相关依赖重新核对。只分析交付报告并结束，不自动采用或派工；历史观察不自动成为本次指定参考。复刻与局部借鉴按需使用项目内参考改编方法，自主创作不加载该方法。


- 统一参考视频任务支持本地当前素材与单条公开TikTok链接，用户选择分析/复刻后即授权该任务获取和进行一次百炼声画分析。复刻再沿原主制片流程接续文字策划，不自动生成媒体。下载失败保留原任务意图，可用本地视频继续；重试只从已完成步骤之后开始，模型失败不自动重复收费。
- 复刻任务指定的模型观察可作为“用户指定参考、模型观察未经人工核对”进入本run参考证据，独立记录request_id、原件hash与analysis_id，不冒充用户逐条确认或商品事实。普通图片/视频分析仍保持原候选选择规则。分析报告同时展示模型观察与限制，不把自动接续当成复刻或成片验收通过。
- TikTok解析使用固定版本库的离线页面解析部分；所有页面、短链、媒体网络请求由工作台自己的HTTPS下载器执行，逐跳验证公开地址并固定实际连接IP与TLS主机。没有浏览器Cookie导入、私有API、挑战绕过、外部脚本或通用URL下载入口。运行记录不保存带签名的CDN地址。

- 参考视频的业务意图是分析或复刻，本地视频与TikTok链接只是两种输入来源。统一参考入口不提供仅“导入参考”的独立业务动作；下载、保存、去重属于后台准备步骤。对话由主制片判断明确的分析/复刻意图，程序校验来源与执行范围；只读/暂停不因此获得创作权限。不能将保存URL或普通上传包装为已完成声画分析或复刻。

- 默认从首页一句话与可选图片/视频开始。发送时自动建立项目并接续第一轮对话；名称、ID、市场与阶段不要求用户填表。上传完整后才启动首轮；失败重试保留同一项目身份，不重复发模型请求。
- 素材入口属于具体项目，只在项目工作区显示；面板标明项目名。首页不得通过记住的run打开素材；切换项目立即关闭并清空旧面板，异步返回不得混入新项目。

- 工作区默认同时显示成果画布与对话。用户路径为理解意图、讨论方案、确认完整方案、查看并确认分镜图、确认视频生成、查看成片。内部四阶段继续作为执行依赖，版本/hash/审核与派工不作为默认导航或用户任务。
- 主制片通过 ask_user 提出一项简短问题、推荐选项及补充文字。问题写入原事件日志，等待答案时结束本轮；回答属于对话，不构成策划或媒体批准。正式采用仍绑定实际展示内容，由用户点击后续接策划或准备分镜，不能因此自动花费媒体生成费用。
- 图片/视频制作确认可嵌入同一工作区；这属于原制作界面的呈现方式调整。准确输入、参考图像素、费用与授权仍需展示，审批与生成接口不下放给 Agent。制作参数由 Agent 准备，手工编辑仅作为高级入口。
- 制作输入的独立文字检查属于团队内部策划工作。主制片可对准确制作草案调用 review_production，沿用本轮冻结的审核连接并记录检查依据；该工具没有媒体生成、图审或费用授权能力。

- 项目状态从既有产物、审核、决定和任务事件派生；不另建任务事实源。任务结束不等于成果通过审核。创作板、对话状态和主制片读取同一项目摘要。首页卡片优先显示需用户处理的项目及其准确下一步；无媒体封面只标明已知内容类型，不用装饰文字暗示制作正在进行或已经完成。
- Agent 工具权限以注册表的角色可用列表、本轮冻结工具集合及领域处理器的校验为准；不用未执行的 READ/WRITE 等标签充当权限机制。
- 本地服务的首页 HTML 不缓存，服务更新后不得让旧首页结构与新静态脚本混用；静态资源继续使用版本查询参数。
- HTTP 服务按学习/交付、项目读写、素材、审批、连接与任务域安装路由；`server.py` 只组合依赖、生命周期和本机边界，不复制状态机。Host 仅接受环回地址；离线测试客户端也使用环回地址，不在正式允许列表加入测试域名。
- 对话最终答复与工具过程旁白分开。过程保留在团队记录；答复先交代本轮成果、实际阻碍和必要决定，不逐条转发内部审核或默认汇报账单。
- 对话气泡以结论为准：澄清与决策选项是结论**之后的独立卡片**，不顶替回复；已结束却没有
  结论回复的回合明说「本轮没有留下结论回复」并指向本轮工作记录；进行中的状态只在任务
  状态行呈现，不提前写结论也不留白。
- 未决问题必须注明责任人（user/team）、处理时机（now/later）与为什么需要该责任人。只有当前有效阶段、明确由用户现在决定的事项进入待答清单。旧问题缺少责任信息时保留为团队待梳理事项，不猜测为用户任务，不抹去问题。**"这一条算不算用户的待办"只维护一处**（`structured.is_user_question`：owner=user 且 timing=now 且有 reason），成果卡片与站内待答清单共用同一判断；`project_brief` 只叠加"是不是当前该问的这一阶段"这层阶段规则，不另写一套行级条件。
- 新阶段优先提交单份结构化内容，由程序生成对应正文；旧正文与旧版本保持原样。结构不完整时明确失败并保留尝试，不静默删除正文。审核检查内容成立与证据，不要求模型再写一份重复正文。
- 重试审核是绑定阶段、版本、指纹的专用任务，只运行独立审核；不重写方案、不隐式批准、不继续生成。复用原任务幂等、取消、连接快照及单写入机制。
- 主制片负责查阅历史、确定素材检查责任、核对系统能力和提出执行方案。用户处境与创意偏好不能升级为市场事实或强制镜头要求；只把确实需要用户提供的事实和决定交还用户。

- 每轮冻结角色连接、价格与业务输入；保存配置只影响后续任务。新 API Key 仅保存到 Git 外的 Windows 用户 DPAPI 加密文件，不进入响应、日志、聊天、localStorage 或 Agent 上下文。开发助手不自动迁移环境凭据或读取 Codex 登录密钥。
- 任务复用原 run 事件、产物、台账，不另起业务任务数据库。浏览器断连不取消任务；重启中断不重放请求，未知用量不影响开始新任务。图片/视频也使用同一 Ledger，不能用文字 token 或文件数量伪造媒体用量；人民币与美元分列。
- Skills 读取 `.agents/skills/`，学习库复用 `tracks/us/creative/learning/library.json`。保存实际角色输入快照、Skill/hash、库版本和用途；快照不证明模型正确使用。案例只能按既有资格召回，不注入 holdout、pending、无用途资格或偏好锚点答案。
- 自然反馈绑定用户原话、run、准确产物版本/hash与范围；模型只提出候选，用户审阅差异后保存。应用前比较库 hash，保留前后版本；等待或局部认可不能转成全面通过。学习库来源登记只保存新链接，不自动抓取或宣称效果；用户明确发起的参考视频任务遵循上方独立契约。
- 显式案例迁移只读原目录，单 writer 锁下隔离暂存、校验后发布；目标存在即拒绝覆盖。原脚本不执行，HTTP 只提供登记的精选文本，商家原素材与生成素材区分；主控可读历史，独立审核不读旧生产者档案。只建立 intake 与 pause，不继承旧审批/费用授权，不自动发模型请求。
- 显式 ContentInput v1 导入由本应用独立校验 schema、来源文件哈希与允许根；不得在运行时导入另一套工作台的源码。只初始化空 intake，不继承包内授权、选择或生成意图。
- 离线测试使用临时 run、临时库与假模型，禁止污染真实案例库或借测试花费额度。真实生成、图片分析质量、视频声画理解和完整模型创作质量未验收，不能用 fixture 代替；既有一次 Codex 连通授权已使用。

## 配置与深入文档

### 独立学习记录（2026-09-24）

- Run 增加 `kind=creative|learning`，旧记录缺省为 `creative`。学习记录沿用同一数据根、聊天、事件日志、素材目录、JobManager 与费用台账；不写入生产四阶段，不得获得方案批准、图片批准或媒体生成入口。
- 学习讨论可以只交付分析。参考观察保留实际媒体版本、来源、覆盖与观察者身份；模型观察及用户允许参考不自动变成人工完整声画复查或市场效果证明。
- Agent 只可在学习记录中整理候选变更，正式共享库仍只有 `tracks/us/creative/learning/library.json`。用户须在界面阅读准确提案与库版本后确认应用；提案、聊天或来源变化使旧确认失效。保存方法与真实任务效果分别记录。
- 新方法经用户保存先为 `trial`，默认不进入普通创作；另经用户确认的限定用途启用提案才可常规召回，仍不声称已验证效果。创作 Run 首次读取的库版本固定在 Git 外，同 Run 明确应用的学习变更可刷新，其他 Run 的后续更新不得静默改写旧任务输入。
- v1 库的 v2 迁移先预览差异，显式应用时保留原字节备份；旧案例、方法 ID、快照与批准历史不重写。开发和测试只用临时库及假模型，不修改正式学习库或调用真实媒体生成。
- 旧创作 Run 缺少完整 pin 时，只用经哈希核对的历史库备份恢复原上下文；找不到原库不得静默装载新版方法。学习提案的 `no_change` 与实际操作互斥。模型观察的声画种类、采样和音轨覆盖由保存的原分析决定，不能由提案扩大。
- 新案例的资源 ID 只能解析为本数据根内准确 Run、素材名及字节指纹；原片变化时拒绝回看，不用同名文件替代。学习 Agent 的历史观察按来源或游标有界读取；人类审阅用完整提案，模型只读不含整库差异的摘要，holdout 内容不能从迁移 diff 旁路进入模型。
- 偏好仅按明确的用户、品牌或项目身份和批准范围回流创作；范围不匹配时不加载，也不把个人喜好当成市场规律或审核结论。尚无可核对身份的偏好只存档，不声称已生效。

`STUDIO_DATA_ROOT` 指定 Git 外数据根；`connections.json` 保存站内连接和角色路由，`config.json` 保存循环限制与可选的旧版预算字段。`STUDIO_BASE_URL`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` 仅用于旧直接客户端兼容路径，站内连接不自动导入环境凭据。服务默认 `127.0.0.1:4760`，无公网身份验证。
