# us-video-studio 目录约定

本文件只约束本应用。跨项目规则见仓库根 [AGENTS.md](../../AGENTS.md) 与
适用的全局规则；当前创作知识位于本仓库 `.agents/skills/` 和 `tracks/us/creative/learning/`；经营事实仍位于可选 `STUDIO_BUSINESS_ROOT` 下的 `tracks/us/`，未连接时需由用户提供准确商品事实。独立仓库的代码/业务/运行数据边界见 [迁移说明](../../docs/migration.md)。本文业务约束继续生效，电商仓库链接用于外部业务约束与历史来源追溯。

## 定位

US 视频与图文策划、受控图片/视频制作的本地独立工作台。站内主 Agent 调配创作角色并自检；独立审核 Agent 已停用，历史审核记录保留。Codex CLI 或用户配置的 API 作为模型连接。**业务运行不依赖当前 Codex 开发对话**，与 [Backlot](https://github.com/Jeffery-Tan/e-business/blob/main/apps/video-workbench/README.md) 分别维护运行状态。

线路归属：**仅 US**。本应用不承载 SEA 任何结论，SEA 不得引用本应用的运行数据。

工作台围绕两条实际任务：一是从有来源的经营与创作反馈完善带货 Skill，停在可核对的知识差异并由 Jeffery 决定是否应用；二是拆解指定爆款视频，将可借鉴的表达机制与当前商品事实分开，再交付针对当前商品的提示词或制作输入。只分析时不自动开始创作；只要提示词时不强制跑完整制片链。专业角色按明确交付需要派工，不为凑齐角色而流转。

首页和项目对话应在上传前直接展示「商品图片/视频」与「参考视频」两个入口；点击后把视频用途带入附件，附件上仍可改。不得因文件类型或“分析视频”四字自行归入爆款参考；商品视频只进入商品素材观察。裸链接用途不明时主制片只问一次用途。上传本身不调用模型，上传视频观察仍由用户在素材区确认费用和用途。用户在对话中明确要求用其提供的 TikTok 链接补全商品信息时，可复用受限下载和百炼声画观察，在当前对话任务中保存 `purpose=product` 候选；该明确请求授权一次观察调用，不建立参考任务、不自动采用商品事实或启动媒体生成。候选须在素材区逐条核对采用；同一轮失败不自动重试，已保存原片与分析优先复用。

TikTok 原片获取保持逐跳域名、公开 DNS 地址及 TLS 主机校验。仅当系统 HTTPS 代理是无凭据的本机回环 HTTP 代理时，允许向它 CONNECT 已校验的数字 IP；不得把原始链接交给代理自行解析，也不得接受远端代理或关闭证书校验。没有合格代理时沿用直连。公开页面响应中的匿名 `tt_chain_token` 只在本次获取的内存中使用，且仅发送给 TikTok 子域名的视频地址；不得读取浏览器或用户账号 Cookie、保存令牌或把它传给第三方 CDN。失败任务保留原链接，用户可显式重试链接或上传原视频；不自动重试。

独立审核 Agent 不再参与新任务，也不构成历史稿的采用障碍。旧审核结论仅供追溯；不再新建审核任务、要求覆盖审核理由或把“通过审核”作为完成条件。执行角色仍须自检实际交付，Jeffery 的阶段决定、参考图确认和媒体费用授权继续按准确版本分别执行。

参考执行绑定本轮真实输入的用途、观察准入、准确参考与最终交付；忙时入站、接续和恢复不得换参考或把依赖分析当成整个任务完成。恢复复用已保存原片和观察，实际 Job 的失败、取消与中断同源显示；不自动重试、不继承媒体生成权限。

正常对话的图片理解也须能在模型设置中独立选择已添加的 MiMo 服务与 `mimo-v2.6-flash`；未明确选择时保留原百炼。图片理解、视频理解和文字角色分配彼此独立，不因主制片或视频理解选 MiMo 自动换图片路由。任务发起时冻结所选连接、模型、配置 revision 与实际输入，使用该服务自己的凭据并在原调用记账；选择无效、密钥缺失、配置变化或提供方失败均停止观察，不自动回退。已有观察继续按来源与用途复用，不因改服务自动重跑。图片仍使用本地像素的 Base64 输入及原有压缩/拆批与停止边界，不把本机路径作为提供方 URL，不增加图片生成能力或商品事实采用。MiMo 图片观察的每个真实调用只发送一张图，首次请求固定使用官方 JSON object mode 的单对象报告契约，不发送工具，也不使用多图 images 数组。报告只有准确来源 id、findings 与 limitations 两个必填非空字符串数组；完整正常结束后，整段 JSON 通过同一单报告字段、ID、条数与原内容长度上限检查才可保存。不抽取 Markdown 或 JSON 片段，不补字段、不修语法；重复键、非有限数、额外字段、错误类型、未知 ID、工具返回或异常结束均停止本轮。供应商仅保证 JSON 语法，不能保证字段与观察内容正确，应用校验与原来源指纹检查不可省略。历史独立 strict function 数据报告能力可保留，但 tool_choice=auto 不能保证返回函数，不作为专用图片观察首请求或失败后兜底。该设置由独立 observer 克隆在首请求前固定，只用于独立图片观察，不改变文字角色或视频理解；失败后不换模式重发。百炼保留原 JSON 批处理。格式检查通过不代表内容成立，原来源指纹与覆盖检查继续生效；格式失败须明确标为模型观察格式不符合要求，不误报连接中断。每图沿原 call_id 记账，失败或取消停止尚未提交的图片，不自动重试或换服务。六张未缓存图片由一次调用变为六次，串行等待及重复的系统/格式输入 token 成本增加，费用以实际台账为准；已有错绑观察不换名、不自动修正，内容正确性须在新隔离项目逐图核对。

同一消息的任务、条件、交付与执行权限继续冻结。若首次解释仅漏填视频用途，可在原
task/constraints/reuse_artifact 指纹完全一致时补齐一次 video_use；引用仍绑定这条已执行
原话，沿原解释追加来源记录，不改旧记录、不替换已绑定用途、不扩展费用授权。补齐前
复核真实用户提供的受限 URL 或当前本地视频文件，来源无效时不占用补齐机会。原链接
与已保存视频仅在同一下载记录及当前字节指纹相符时视为同一来源；按这些别名核对全部
附件用途，任何明确冲突都必须拒绝。UI 已保存的完整回答被模型用真实子串再次记录时
幂等返回原记录，不要求用户重答、不改写其原话。

仅查看图片是只读分析，不要求创作路由、素材方案或阶段决定；任务解释中的 `photo` 在此表示源图片，不改变项目的交付格式。可选 `image_use` 绑定执行中的真实原话与准确图片名、原图指纹及用途；省略时服务端按本条附件或当前唯一的完整源图集合固定目标，模型选择少量图片不能缩小整组交付。明确子集须有准确来源绑定，歧义不猜。绑定沿既有输入/解释事件保存，不新建观察状态库，不授予创作、商品事实采用或生成权限；视频用途仍走原视频准入，不因 `photo` 字段变成图片分析。 纯图片分析解释（`analyze/analysis`、`photo` 或兼容的 `none`、无视频用途绑定）在首次落盘前必须核验 `allowed_stages=[]`，不因省略可选 `image_use` 跳过；不相容的创作阶段直接拒绝并说明可纠正字段，未落盘的错误允许同一真实消息重新提交准确解释，不清空模型字段或改写已绑定的历史解释。

主制片只对核验通过、正在执行且尚未解释的真实新 receipt 使用首次八项 strict 工具清单；展示及当前状态均无待决、待答问题，且无反馈对象、内部接续或参考恢复时才可进入，无法核对时保留原工具机制。新 receipt 不限于新项目：已有分镜但无上述待决状态时仍先解释完整当前原话，绑定后制作回到原工具机制。首次清单增加准确版本的 read_artifact，保留完整 typed task interpretation 与解释加图片观察的 combined 入口，不按消息关键词决定意图，不自动补 JSON 或重发。已经绑定的纯图片分析使用五项 strict 读取/观察清单，不混入创作写稿工具，也不重复创造任务解释。每次模型请求前由可信状态选择并冻结清单与 schema；整个返回工具批次先核对该准确 manifest，再执行原 handler，状态变化只影响下一次请求。未知工具、重复调用身份或 strict 参数不合 schema 时整批不执行并终止，保留已收到的用量，不再请求模型修补。自然决定、同轮回答、制作准备、参考恢复及其他任务保留原机制；创作权限和费用边界不因 strict 改变。可选对象只沿准确应用 wire schema 的固定字符串还原省略语义，原响应与私有回放不改写；标准 typed schema 不宣称保证 JSON 语法。

首次八项中的 observe_images 组合入口仅受理纯图片分析：analyze/analysis、allowed_stages=[]。创作请求须先用 propose_task_interpretation 沿 record_task_interpretation 保存完整本轮任务与条件，包括当前方向交付及之后的创作要求；下一次模型请求才按原机制选择创作范围并观察素材，不在同一返回批次绑定创作解释并调用纯分析组合入口。说明不改 schema、枚举或状态清单，不省略条件、不修参数或自动重发；严格返回不符合本次枚举时仍整批拒绝，不能猜未保存的错误值。非写稿工具的格式错误对用户称为本次工具格式，不误称脚本提交格式。

静态图片观察的首请求及主制片汇总须在每条正文中区分可见形态、功能或材质推断与图中文字宣传。仅看到钩扣形状、灰色光泽、黑色绑带或分离肩带图示时，按这些形态描述；未操作拉伸或拆卸，不能断言弹性或可拆卸，光泽与形状不能确认金属或塑料。图上容量、材质、保温或防水等文字须注明“图中文字写着”，不能直接变成已验证商品事实。数量或细节不能辨清时明确未知，不按常识补齐。汇总须保留这些证据性质，包括复用旧观察；无其他当前已采用且可核对的依据时，不把观察中的功能、材质或宣传说法升级为确定事实，也不能用末尾泛化免责声明抵消正文肯定。保持原报告字段、来源指纹与保存记录；内容约束是请求及上下文要求，不冒充模型已遵守或事实已验收。

首页、项目摘要与画布的纯图片分析状态共用准确 Job、真实已执行消息、冻结任务解释及逐图覆盖投影；只有该 Job 正常结束、准确分析交付与全部当前来源观察齐备且原最终回复已保存时显示完成。部分观察、失败、停止或来源变化仍显示未完成；连续可信纯进度查询可保留原已完成报告，新创作解释或产物不能借它完成。原回复只读展示，不修改历史记录、项目创作格式或执行权限，不从消息关键词或模型叙述推断成功；标题只从首个主题子句提取形式，后续限制里的“视频”不变成交付名称，已保存及人工标题不自动重写。图片分析完成以固定目标和真实已保存的逐图观察覆盖核对，不以一个布尔值或“参考视频报告”代替；来源字节、用途、观察身份及可见内容/限制均须可核对。缓存只有用户明确发起本轮观察后才可复用，不能由历史状态查询触发付费重看；部分失败保留此前观察，未观察项明确缺失，不自动重试。格式失败在原调用下追加白名单结构诊断（固定字段存在/类型/数量及正文体积/指纹），不保存模型正文、未知键名或私有思考，也不放宽字段/来源检查。

商品和参考附件共用草稿事务，保留文字、用途与上传回执。结果未知时核对原冻结载荷；明确拒绝后允许纠正并建立新提交身份。忙时移除未发送附件只改变浏览器草稿，不改项目素材或停止任务。具体输入、上下文与恢复约束见[开发契约](docs/development-contracts.md#面向创作者的统一交互契约2026-09-21)及[参考修复记录](docs/reference-video-audit-20261003.md)。

素材计划的 items 只列当前采用方案实际需要的素材，一页或一镜可有多项来源，行数不能冒充目标页数/镜头数。已明确排除的主张、画面或真实性证据放在正文或 gaps 的可后补说明中，不能作为无法获得的必需素材写入 items；已排除不等于证据已经获得。角色系统与提交工具使用同源字段说明；原无法获得条目和 blocking=阻塞 仍按原规则阻断写稿，不按标题、备注或模型说法自动识别排除、改状态或修旧稿。阅读标题只称实际素材项数及待解决项，不声称整套作品做不出来。

## 什么放哪

| 路径 | 放什么 | 不放什么 |
| --- | --- | --- |
| `studio/` | 应用代码。领域层（`models`/`store`/`pipeline`/`ledger`）与 Agent 层（`agents/`）、工具层（`tools/`）、HTTP 组合入口（`server.py`）和分域路由（`http_*.py`）分开 | 真实运行数据 |
| `studio/web/` | 原生 HTML/JS/CSS 前端，不引前端框架 | 构建产物 |
| `<app>/scripts/` | 本应用启动与开发工具：`start.ps1` 做诊断后启动，`seed_preview.py` 造假数据预演界面。**注意与仓库根的 `scripts/` 是两个目录**，后者放共用业务脚本 | 业务脚本 |
| `tests/` | 离线测试。**默认全部不联网**，用假模型覆盖循环与状态机 | 需要真实 API 的用例 |
| `README.md` | 定位、启动、运行契约、恢复命令与两套工作台的关系 | 逐次运行记录 |
| `requirements-local.txt` | 本机额外依赖及版本 | 全量生产依赖 |

真实运行数据必须在仓库外，以服务的 `STUDIO_DATA_ROOT` 为准；未设置时的历史默认值为 `J:/E-Business-Video-Data/us-video-studio/`。不要把默认值当作当前机器已使用的数据根；实际启动与恢复入口见 README。
素材（图片与视频）属于运行数据，同样不进 Git。
代码与非敏感配置示例进 Git，实际连接配置、凭据与运行数据不进 Git。这与 `apps/video-workbench` 的既有做法一致。

## 命名

- 阶段名用 `snake_case`：`intake` / `direction` / `material_plan` / `writing`。
- 角色名用 `snake_case`：新任务使用 `orchestrator` / `director` / `material` / `writer`；`reviewer` 仅用于历史记录与兼容字段。
- 运行目录 `runs/<run-id>/`，`run-id` 用 `[a-z0-9][a-z0-9-]*`。
- 素材放在 `runs/<run-id>/materials/`，**文件名保持磁盘上的原样**——产物里的
  `file` 字段就是靠这个文件名找到它的。中文名、空格、大小写都允许；
  路径分隔符不允许，见红线 7。
- 产物文件名由阶段决定：`<stage>-v<n>.md`，版本号只增不减。
- 测试文件 Python 用 `tests/test_<模块>.py`，前端渲染器用 `tests/js/test_<模块>.mjs`。

## 什么时候清理

- `runs/` 下的运行数据**只标记不删除**。过期靠状态与 `history/` 表达，不靠删文件。
- 用户可从项目卡片或工作台删除项目，删除前展示项目名和影响；删除写入原事件日志并移入界面回收站，不移动或清除运行目录。回收站可恢复原项目，保留素材、对话、版本与调用记录；删除状态下禁止继续调用模型或生成。正在执行的项目须先停止并等待任务结束，删除不得暗中取消任务。台账汇总继续包含已删除项目。
- 产物不可变。修订产生新版本，旧版本留在原地。
- 本目录内不留临时文件；需要暂存写到系统临时目录。

## 命令

安装、显式选择数据根、启动及 Python/Node 离线测试命令统一维护在 [README 的启动与检查](README.md#启动与检查)。不要复制旧机器的盘符启动另一个空数据根；更新前核对监听进程与活动任务，静态文件刷新不能证明后端已加载。 本机 HTML 与静态代码资源须在刷新时重新验证，避免浏览器沿用旧脚本/样式；首页每次响应按各静态文件的实际内容指纹生成资源版本 URL，内容未变则 URL 稳定，内容更新则 URL 改变，不用固定日期、文件时间或随机值代替。后台指纹更新也不能证明前台已加载新代码。

展示函数优先保持可在 Node 中独立测试；页面控制器可使用 DOM。`blocks.js` / `md.js` 的转义与渲染不依赖浏览器或 jsdom，修改后必须运行 README 中的 Node 测试命令。

DeepSeek 编剧的首次请求使用完整非流式返回，保留原模型、low 思考强度、严格工具及提供方默认输出额度；其他角色和 MiMo 继续原流式路由。等待仍显示同一调用的时限与停止状态，不能把没有增量说成故障或完成。此设置在首次请求前明确确定，不在失败后自动切换模式或重发。

单次等待与停止：DeepSeek、MiMo、OpenAI-compatible 与 Anthropic-compatible 的单次模型调用从发起请求前计算 600 秒总时限，连接等待、保活与模型增量都不能延长；超时终止本轮且不自动重试。两种兼容路由也须将用户停止传入在途请求，在等待响应头、静默正文与持续保活时关闭原连接；不以遗留后台请求线程模拟取消。公开等待事件仅含已等待秒数、剩余时限、是否收到有效模型增量；保活不代表模型已经回复，私有思考和未完成工具参数保持不可见。停止优先于时限，关闭在途请求；停止须丢弃尚未接续的旧调整，重启不恢复取消任务。未完成响应的用量保持未知，已保存产物与真实用量保留。 Codex 图片任务使用有界 RPC 轮询，停止后只对已经核验的准确 thread/turn 发送一次 turn/interrupt；停止检测、等待原结束回执与本地 session 清理共用五秒窗口，窗口届满即结束本地等待，不以关闭本地进程冒认提供方已停止。只有最后一次发前停止检查通过并进入原 turn/start 管道写入才记为可能提交，写入失败仍保守保持未知；发前已停止则明确没有模型请求。turn/start 回执尚未取得准确 turn 身份时不得猜测中断对象；已提交结果与图片费用保持未知。窗口内到达且通过原字节校验的图片及实际已读用量仍保留，取消不得提升为成功、图审通过或零费用，不重发生成、不提交后续图片。

## 本应用红线

1. **生成仅由用户在制作界面明确提交。** 图片走 Codex CLI，视频逐段走百炼单首帧链路；Agent 可准备并自检方案，但不得批准图片、授权费用或提交生成。准确输入由用户核对；每段视频只接收本站按图片字节指纹获批的参考图。整组视频须按已展示的分镜顺序与逐段费用一次核对后顺序提交；一段未完成或提交结果未知即停止后续提交，不自动重试。全部视频取回后可按绑定当前脚本的准确剪辑计划在本地截取、复用、叠字与拼接，计划须列明每次取用的片段、时间范围、声轨来源和顺序。拼接不发起媒体生成或新增提供方费用，需保存剪辑计划及输入片段的版本与字节指纹。实际声画和内容仍需播放验收。真实生成的验收费用另行确认，离线测试不联网、不花钱。
   整组生成的本地预检可在同一项目可重入锁内，对本次准确输入集合复用已经完整核验成功的制作输入；键必须包括项目、输入身份、预期指纹与来源检查要求，返回独立副本。复用只限本次预检所属线程，退出或异常后立即清空并失效，不存入服务或跨请求缓存，不进入生成执行闭包。单项提交默认仍重新读取；下一次请求、批次开始执行及每次提交提供方前，原整组授权、来源、模型 revision、参考图字节与费用检查均重新核验，不能使用预检的旧通过结论。预检本身不调用生成或写入生成意图；坏项目、变更来源及不准确授权仍阻断。
2. **Agent 不得自行创造、批准或伪造用户决定，也不得直接写入用户授权记录。**
   来自真实用户消息或 UI 的决定，必须由可信服务端绑定准确对象、版本和当前状态后记录；
   Agent 只能提出动作候选（`propose_user_action`），由服务端重新推导当前候选并复核后才落盘。
   按钮点击与对话原话都只是输入渠道，写入点只有 `Pipeline.record_approval` 一处，
   两条路径共用同一接续派生（`decision.continuation_text` / `continuation_request_id`）。
   对话决定的核验不靠关键词：判断的是「当前运行状态是否唯一地提供这个动作」，
   有歧义时澄清而不是猜；不得用推荐项顶替用户指名的选项，也不得把模型改写的要求
   记成用户的话（`decision.accepting_user_words`）。
   自然采用先定位本条原话中完整的决定子句，并绑定当时显示的准确对象；用户引用该对象的准确标题不等于转述他人，后续意见里的问题或后续阶段名不等于第二项决定。不得用任意子串删掉否定、条件或他人转述来制造采用；完整原话仍保留用于暂停和后续要求。已核验的原话子句须沿候选到提交保留，并在落盘前再次从原 receipt 复核，不换版本、不继承费用权限。
   引号、他人转述与选项身份的拒绝检查针对完整首个决定子句，不能因后续文案纠正带引号或提到 A/B/C 就否定开头已明确的采用。条件仍按整条原话保守拒绝，因为后续条件可能限定采用或接续何时生效；不从首句制造无条件执行。后续完整子句仍核对真正的第二次采用和撤回，完整原话仍用于暂停及接续要求。明确采用动词加准确选项后可带有界的“的……主线/路线/思路”描述；单独描述、比较、问题、否定、条件及他人转述仍不成为采用，不自动识别意图、改写原话或替换准确产物。
   **收费或外部副作用动作必须使用独立的一次性 Execution Authorization**：
   自然语言只能推进到准确的一次性确认（绑定项目、源版本与指纹、逐项输入、模型、参数、
   数量与已知费用），提交仍走制作界面原有确认入口；Creative Decision 不得自动升级为执行授权。
   详见 [对话控制模型](docs/conversational-control.md)。
3. **两套工作台分别维护，互不写入运行状态。** Codex 驱动的 `apps/video-workbench`
   保留原记录，独立 Studio 需独立验收；显式迁移只读原件，不自动迁移历史批准。
4. **不把技术成功当内容成立。** 渲染成功、字段非空、哈希校验通过都不等于内容可用。图文项目的当前写稿决定沿已保存的明确 photo 格式称“图文方案”，修改/确认按钮、作品阅读页标题及导航、下一步逐页图片输入使用同一名称；图文阅读页按页说明画面与文案，并将补充依据称为逐页安排。只有当前可信 photo 格式改变阅读页称呼，不按模型页码文本猜测标题；视频及历史未知格式保留原称呼。 单张制作弹窗与生成确认也沿同项目 timeline 的明确 photo 形式和服务器准确页序称页与图片；形式不能核对时保留兼容称呼，页序缺失或歧义时不猜。只改只读投影文案，不改历史原件、决定载荷、版本/hash、审批动作或生成权限。
5. **费用台账记全。** 调用先记 intent，再记 settlement；未知用量或金额不得补零。
   Jeffery 于 2026-09-21 明确：当前为个人工作台，不需要手工核账功能。未知用量仅保留排错记录，不阻断后续调用，不要求用户填写 token/费用；账单以提供方平台为准。当前不设工作台全局 token 或美元额度；历史用量照常记录，金额只是估算。显式配置的旧数值上限仍兼容。
   内容失败与用量状态分别记录：完整非流式响应已返回合法输入/输出计数时自动记账，正文或工具参数解析失败不使该用量变成未知；流式中断的部分计数仍保留未知，不补零、不阻断。
   模型响应校验失败须在原调用下保留安全诊断：失败字段、错误类别、结束原因及必要的体积/位置/指纹，不保存原始正文、推理或工具参数。提供方明确中断、无效工具参数与工作台解析失败分别呈现；失败响应不执行工具、不自动重试。
   工具参数 JSON 拒绝须分别记录原字符串字符数与 UTF-8 字节数，Python JSON 错误只映射固定类别，不保存错误 msg 或附近正文。工具名只允许来自本次冻结请求实际声明的集合，未知或未声明名字不持久化；完整传输、真实用量、整批不执行及不重试的边界保持，历史缺失诊断不补造。
   仅对已完整接收、以 `tool_calls` 正常结束的 DeepSeek 完整编剧提交允许一项有证据的格式处理：本批只有一个 `submit_stage`，原 JSON 错误确在 EOF，词法状态只缺最外层一个 `}`，才可在独立副本追加该字符。完整性只能由读完 HTTP 正文或核验结束事件与 `[DONE]` 的真实传输入口提供；裸解析字典、`length`、缺结束事件、中断及取消均不满足。候选须通过本次冻结的应用内 video/photo 完整编剧 strict schema、canonical shape 和零字段丢弃校验；拒绝重复键、非有限数、内层括号、字符串、escape、逗号错误、缺字段、补空字段及其他工具。拒绝时可沿原调用记录固定类别的词法/候选校验原因及应用 schema 白名单路径，不能保存失败原参数、未知字段名、内容或私有思考；诊断不改变接受集合、不补内层括号、不执行被拒绝工具，也不触发自动模型重试。
   此格式处理的窄例外是：候选全部格式校验通过后，允许把原 arguments UTF-8 字节保存在原调用的私密、不可执行证据文件，执行副本另存；不保存 reasoning 或完整 wire response。公开只记录原件/候选/schema 指纹、体积与固定处理方式，证据写入失败则不执行。历史回放必须区分模型原件与处理副本，不能把处理后的输入冒充原始返回，也不能在恢复时自动重放工具。scope、attempt、上游版本、shot identity、visual design 及停止状态仍在原提交锁内核验；业务拒绝保留失败事实并终止本次处理路径，不自动再调模型或把格式处理称为写稿成功。
   DeepSeek/MiMo 的流式读取按完整 SSE 事件组装，允许保活及独立用量片段；正文结束原因与
   `[DONE]` 都完整收到后才交付。HTTP 200 内的错误事件仍是提供方失败，不能当作成功或
   笼统的 JSON 错误。诊断绑定真实提供方、固定字段与错误类别、片段序号/体积/指纹；不保存
   错误原文或私有响应。中断、超时或停止时已读合法计数按部分用量保留，不确认最终用量
   与费用，不重试或自动改用其他服务。
   DeepSeek/MiMo 非 200 响应同样在原调用下记录安全诊断：HTTP 状态、固定错误分类、
   白名单中的提供方错误码/参数路径、受限读取的体积与指纹，以及实际传输配置和请求指纹。
   错误体只在内存中有界读取，停止与截止时间继续生效；不保存原文、密钥或请求正文。
   传输中断须沿原调用保存实际请求的 strict/thinking/思考强度/流式/输出额度、固定异常类别及有界计数和时间统计；连接等待、读取超时、远端协议断开与总截止分别标识。计数不保存正文或私有思考，也不推算费用或任务完成；原停止、未知用量和不自动重发边界保持。
   认证、余额、限流与服务故障不得误报为 strict schema 错误；没有明确字段依据时只说
   请求被拒绝，历史缺失的拒绝原因不得补造。所有非 200 请求停止本轮，不自动重发。
6. **改规范先改本文档，再改代码。**
7. **素材只往 `runs/<id>/materials/` 落，且只能是图片与视频。** 上传不直接创建阶段
   产物或批准；素材字节与观察摘要变化必须使相关依赖失效。落地前检查扩展名白名单、
   单文件大小上限、解析后路径位于素材目录内；保留合法文件名，拒绝同名覆盖。
   大图进入图片观察时自动准备压缩副本，优先保留分辨率；原素材与获批制作参考图保持原字节。
   观察记录绑定原图指纹，并记录实际发送副本的指纹、尺寸、体积与处理方式。多图按实际输入
   体积分批，每批成功即保存；输入预检失败且尚未调用模型时可修正，已调用失败或结果不明
   不在同一轮自动重发。压缩和拆批不调用生成模型，不增加批准或制作入口。
   失效判定用**事件世代（generation）单调前进**，不依赖内容哈希回等：产物写入时冻结
   当前证据/参考世代，世代前进即永久 stale；即使内容回到历史哈希（A→B→A）也不得使
   旧批准复活。素材上传须写入 `material_uploaded` 事件以推进证据世代。
   推进世代与改变证据指纹的只有**源事实**（素材上传/导入、观察、非自主的创作模式选择）；
   本 run 自己生成的产物是派生物：出片时它会同时写入 `material_uploaded` 与
   `production_output`（两者同一 `(name, sha256)`），这两条都不推进证据世代、也不进入
   证据指纹——否则一次成功出片会作废授权它的脚本。判定按 `(name, sha256)` 成对匹配，
   生成文件事后被改字节即重新算源事实。派生物仍保留在 `evidence_snapshot` 的 agent
   上下文里并标注 `origin='generated'`；过滤只有一处（`evidence.derived_outputs` /
   `evidence_source_snapshot`），制作基线与阶段失效共用，不得由两个模块分别定义。
   主制片观察本 run 自产图片时，仅含观察之前已登记的准确 `(name, sha256)` 派生物的
   `agent_images_observed` 事件也不推进源证据世代；混合源图、不同字节或身份不明的观察
   仍按原规则推进。观察记录与真实用量保留，不能因此把生成图变成商品事实。
8. **审批绑定用户实际阅读的版本。** `expected_version` 与 `expected_artifact_sha256`
   必须对应展示内容，哈希须是 64 位小写十六进制，不得静默换成最新版；`selected_option_id` 是正式选择，推荐不是选择。历史原文读者的异步请求只允许最后一次选择更新界面，不能让旧请求回填新版本。
   `artifact-v2` 覆盖正文、结构、证据、限制及依赖；`body-v1` 只回放，不继承旧批准继续制作。
   **同一版本只允许一次决定**：当前最新版已有 `approved`/`approved_override`/`returned`
   时，拒发新 nonce、拒绝新决定（不得覆盖 `selected_option_id`）；同一 nonce 的重试保持幂等。
   退回后须产出新版本才能再次决定。**界面与该规则同源**：同一版本已有决定时 `can_approve` 为假，
   决定卡片与 journey/stage 两个 gate 都不再提供第二次决定，不得给出服务端必然拒绝的按钮；
   历史独立审核退回仅供追溯，不占用该版本的用户决定，也不要求具名覆盖理由。
   用户明确要求修复误扩大的项目时，可通过站内恢复入口追加 `artifact_versions_withdrawn`
   停用尚无用户决定的准确版本，保留全部原文件、批准与用量。当前产物投影统一从 Store
   读取，历史查询仍含停用版本，新版号从全部历史递增。预览与应用绑定同一状态指纹，
   应用前复验旧稿、原批准和制作基线；真实来源变更、未结束任务或阶段不允许恢复。
   不写新批准、不把旧批准转到新稿，不清除证据世代；Agent 没有该恢复工具。
9. **同一数据根只运行一个写入进程。** 现有锁不代表多服务写入支持；本地输入导入与阶段
   恢复前停止对应服务。使用 README 中的显式恢复入口（CLI或站内运行控制），不删除历史或清零台账解锁。
   本地启动脚本默认独立后台运行并启用后端热重载。监督进程另持操作系统锁，代码变更稳定后仅在
   JobManager 与 Codex 登录均空闲时、按既有 jobs 锁顺序关闭任务入口，再正常退出旧进程；确认旧
   进程退出后才启动新进程。不取消在途任务、不自动重发请求、不监听运行数据或凭据文件。
   语法错误保留旧服务并报告；启动失败保留诊断，修复代码后恢复。运行信息显示实际重载状态，
   默认启动重复执行只连接匹配的数据根与热重载服务，不抢端口或强杀未知进程。
主制片与页面制作读取须共用原 Ledger 的有效调用记录，含历史用量修订；没有服务实例也须读取同一台账，不因漏传 Ledger 把已提交任务说成未开始或跳过原任务核实。台账损坏须明确失败，不猜零费用；此读取不修改调用或任务状态。

模型只读制作记录默认提供原制作投影的状态与身份清单，仍保留所有当前/历史输入、准确来源与页序、引用、失败原因和全部未决任务；不把每份输入的完整编译描述在 prompt/compiled_prompt/request_payload 等别名中重复发送。需要核对或修改原描述时，read_production 以准确 draft_id 与 expected_sha256 同时读取该份详情，完整 shot_prompt 与 compiled_prompt 各保留一份，不能猜最新、截断原文或赋予执行权限。保存输入回执只给准确身份/引用与详情读取入口，画布及费用确认仍完整读取原制作投影。工作计划中的运行索引保留全部任务身份、状态、原因、停止与交付回执；只在本轮任务及所属角色保留完整能力/上下文引用，不反复附所有历史任务的能力清单。此处只改模型阅读投影，不改变 Store、制作状态、请求载荷、校验、审批、收费或原历史记录。 准确输入详情只返回这一份原描述，不重复整个历史输入与素材清单；仍附原目标/逐镜状态、全部未决提交与全局准备阻断。所绑定写稿来源以准确版本与指纹重新核对，仅在 artifact-v2 的指纹同时覆盖正文和 structured 段落时，复用 target_shots 的同一镜头身份规则返回该段完整原文；旧 body-v1 未覆盖 structured 元数据或无法唯一关联时明确缺失，不猜最新方案或用历史段落位置顶替。完整状态清单仍用无参数读取，原画布 HTTP 详情不变。

已绑定的纯只读请求（status/discuss/clarify、follow_up、allowed_stages=[]）只有真实执行中的用户收件、已展示上下文与当前无待定决定/问题同时核对后，才缩小本次模型工具清单与系统上下文；内部接续、反馈/参考恢复、收费或执行目标、附件观察用途及历史回放仍走原路径。不按消息关键词或尚未落盘的解释选分支。同一次请求的系统上下文沿已冻结工具清单的同一分支，完整保留 COMMON、项目需求原话、已绑定本轮/项目/回复条件与方法依据，不重复创作产物全集；当前状态摘要与实际台账费用沿原读取方式附入，未知金额/用量不猜。只读清单提供准确状态、产物、历史、方法及原 ask_user 澄清入口；能力目录不扩大本次工具权限，不包含观察、写入、派工或收费生成入口。工具批次仍按已发送清单整体校验，不拆断历史工具调用与结果、不截断原描述、不新增权限或自动重试。 可信 initial 入口同样使用阶段对应的短上下文：完整保留原话、项目状态/身份、条件与方法，只指导真实最终任务解释与必要澄清；任务 schema 与提示共用只读语义：仅核对已保存稿件/制作原描述或答复历史状态、且不要求改稿或新创作交付时，使用 status/discuss + follow_up；analyze/analysis 指准确图片/视频/参考来源的观察分析报告，可复用满足原覆盖与来源核验的已存观察，不要求再次收费查看。文字核对不等待参考报告，核对并改稿仍按原 revision/创作最终交付。纯图分析仍按原 combined 契约；创作中的观察依赖不能把最终交付降为 analysis，其余工具只在解释落盘后的下一次请求开放。read_capabilities 的 tools 与执行提示沿该次冻结清单返回，应用能力摘要不能把未开放工具说成本轮可执行；专业角色及不带请求清单的原读取保持兼容。

10. **角色上下文保持隔离。** 导演只读当前目标与必要已确认条件；编剧与素材统筹只读必要事实、真实所选方向及素材证据。文件存在不代表已观察，导入观察不代表模型亲自看过。
11. **输入不携带隐含权限。** ContentInput 仅从明确允许的本地根导入空 intake，拒绝覆盖；
    不增加任意文件 HTTP 读取入口，不把包内授权字段转成图片、视频、费用或发布授权。
    attempt `token` 可留在服务端事件日志供提交校验，但 HTTP 读接口（`/events`、SSE、
    timeline、job 事件、`/state`、`/recovery` 等）一律经共用 `redact_http_event` 脱敏，
    不得在任一出口返回该明文；台账/未决调用查询必须按 `run_id` 过滤，不得跨 run 汇总。
   参考选择与源案例内容的世代与观察同构：凡绕 API 改动参考侧车/源案例而未写入
   `reference_selected`/`reference_removed` 等世代事件的路径，须在读路径检测到源变化时
    补写世代事件，使 A→B→A 永久 stale；不得仅依赖内容哈希（当前由 `reference_source_changed`
    承担：按 `(case_id, current_sha256)` 幂等，只记本 run 自己选中的案例，不牵连未选择该案例的其他项目）。
12. **阶段确认按钮文案只维护一处，且对话原话与按钮同源。** 对话区的 stage gate 是当前版本
    的正式决定入口之一；作品阅读页也可提供同一准确版本的采用、退回与回答入口。
    approve/reject 标签由 stage 的共享文案源维护，note/override 要求由 `wireGate` 与服务端
    `record_approval` 对齐，不再维护第二套决定表单。
    用户在对话里说出的同一决定（`propose_user_action` → `decision.commit`）与点击走同一条
    写入与接续路径，界面文案不得暗示"只有点击才算决定"。

13. **用户决定与接续意图同版保存。** 对话与画布复用同一准确对象、`gateHtml`/`wireGate` 和服务端决定写入点，不建立第二套批准或状态。
    用户点击“采用并继续”或“退回并修改”时，把接续意图随批准记录持久保存，由服务端用该批准
    派生固定 request_id 提交后续策划任务。同一点击重试只查回原任务，不重复发模型请求；若决定
    已保存但任务未创建，页面明确显示待接续并允许用户点击重试。服务重启不得自动重发已创建的
    任务。该意图只覆盖后续文字策划和制作输入准备，绝不批准图片、费用或视频生成。脚本采用卡须明确随后准备实际分镜输入供核对；准备不产生媒体生成费用，文字模型用量仍记录，图片与视频生成分别确认范围和费用，不宣称整个制作链已结束或后续不会收费。
    真实 UI 采用后的可逆接续范围由服务端从原批准、准确 stage/version/hash 与当时唯一可用下一步冻结；执行与每次写入复核同一批准和仍有效的源。该来源不是新用户原话，模型不得另造任务解释、改变格式/参考/业务条件或扩为媒体生成；未知下一步、源变化或失效即拒绝，重复请求只查原任务。准确准备任务已明确 blocked/failed 且项目空闲时，可由用户在同一决定回执明确新建准备请求，绑定原批准和失败任务并复核当前完整源；不重采用、不重放旧请求，停止、未知或仍在执行的结果不提供重跑入口。自然对话接续仍保留真实完整原话及其条件，不迁移批准或费用权限。

14. **运行诊断不得改写业务状态。** 启动前 doctor 只检查所选解释器、依赖、明确数据根、
    writer 锁、监听端口和本机媒体工具；不创建新数据根、不读取凭据明文、不测试付费模型。
    站内诊断显示本进程启动时冻结的提交版本、本地修改标识、代码指纹、启动时间、数据根标识和依赖状态；没有 Git 元数据时保留未知，不声明最新版。
    不能把“已配置”写成“真实模型已验证”。
    本地启动默认监测后端代码与受控方法包变化；内容稳定且语法可解析后，等待 JobManager
    空闲，在同一任务锁内关闭新任务准入，再经正常服务生命周期退出、释放 writer 锁并重启。
    不强制停止在途模型/媒体任务，不重发历史任务；语法错误保持旧服务并显示待更新状态。
    监听仅用于本地开发更新，不新增远程重启入口或修改执行审批策略；`-NoReload` 可禁用。

15. **Skill 依赖通过受控方法包读取。** Agent 可见目录与 `read_method_document` 使用同一白名单；
    方法卡只放可执行的稳定规则，标明来源文件与适用角色。历史案例、用户反馈、研究比较与
    holdout 答案继续走原资格过滤和人工审计入口，不因 Skill 相对链接而整篇开放。
    包级检查须验证登记文件存在、角色权限和工具映射，不授予新的生成、审批或费用权限。

16. **Codex 模型选择来自本机目录。** 角色配置可只读调用本机 Codex app-server 的
    `model/list` 展示该登录与客户端返回的可见模型；不硬编码可用型号，不把列表读取说成模型
    调用或额度验证。空值仍表示沿用本机默认模型；已保存但暂不在列表的模型保持原值，须由
    用户主动改选。列表读取不读取或回显凭据，不改角色设置；保存后仅影响下一轮冻结的连接快照。

17. **创作者界面按作品、目标与下一动作组织。** 项目默认进入同一张创作画布：需求与素材、共同人物/场景及逐镜方案、按镜头对应的真实结果横向关联；详情按需打开，不默认堆叠历史输入或六组成果页签。标题在项目
    选择器、实时状态在任务状态行、下一动作是工作区顶栏的单个中性入口——**不设常驻状态
    横幅**，状态与结论以对话流为唯一主轴（与成熟开源对话工作台一致）。内部阶段、完整
    图文 image 输出是含采用稿准确图内文案的完整静态页面，不是视频无字首帧。共享编译器从可信 photo 形式和准确 writing 段落取得 line 与换行，放入最终页面输出契约；caption、alt text 与厂商声明不印入图。不能承诺尚不存在的静态图片后期自动叠字链；审阅包复制原图、另列文案不等于图片已合成文字。新增契约不重写历史草稿或迁移生成授权，旧输入须显式重新保存并核对新指纹；生成后的实际文字、结构与手机阅读仍需验收。视频首帧不因存在台词而强制印字。 图文整组确认按服务端准确页码展示图内文案与共享设计；未知提交的核实入口不因文案字段暂缺而被隐藏，但新的确认必须能读取准确文案。整组任务在准备时冻结可信形式，图文进度与完成提示按页表达，不引导接续视频；子集任务的实际页码仅从制作端当前准确输入、指纹与 shot_id 唯一对应的 coverage 页序冻结，另列本次数量，不能把批次序号冒充页码。页序不可核对时仅说明本次数量，失败仍停止尚未提交的所选项；原历史状态与在途任务原记录不重写。
    Prompt、尝试记录、ZIP、模型配置和诊断按需打开。图文和只分析项目不得默认显示视频成片占位。交付形式尚未可信绑定时，画布和作品页使用中性的方案与作品称呼，不默认视频；仅可信 video 形式展示视频记录入口。图文按页展示方案与图片结果，不用镜头、口播或视频称呼；不按用户消息关键词猜测形式。首页与当前工作摘要的写稿称呼共用已有可信交付形式：photo 为「图文方案」，video 为「脚本」，形式尚未确定时为「创作方案」；不改任务阶段、下一动作或历史稿件。
    新项目自动命名只从创作请求文字提取主题与交付形式，忽略 URL，不把 https 或链接片段当商品名称；只给链接时使用中性日期名，不推测用途。不改写原始需求或既有项目名。
    标题派生可去掉开头明确的附件引用（如“用附上的”“使用附件里的”“根据上传的”）及其末尾来源标签，保留实际商品或主题；“附上”、附件指示和无主题的“商品图”不作为项目名。无可读主题或形式时沿用中性日期名，不从后续禁止事项推断形式；此处理只用于新自动标题，不解析业务意图、不调用模型或重写已有名称。
    当前任务的缺失交付、局部修订完成、设计补充及输入就绪提示也按同一项目可信形式称呼图文方案/脚本/创作方案与逐页图片/分镜/创作输入；未核对任务、当前项目与timeline身份时使用中性名称，不拿其他项目的形式或消息关键词改称。准确字段直接修改的发送按钮沿当前项目与目标身份称为修改图文方案/脚本/创作方案；完成回执用实际保存的版本号，不能用会被界面隐藏的内部产物句柄代替。画布的当前写稿方案与对话成果入口复用同一只读方案阅读页，按已展示且仍匹配的版本/hash 打开；旧版、过期或无法核对的稿件继续通过原准确版本记录阅读，不猜最新版。只读方案阅读页沿准确产物正整数版号显示第几版；正文引用图片标为方案参考图，与画布制作结果分清，不凭图片存在宣称成图。提示不改变原缺失字段、阶段、任务结果或执行边界。
    页面初始化先显示默认首页，再异步恢复项目；初始化完成不得再次切换工作区。恢复期间用户打开
    当前项目或切换作品，以当前选择为准，迟到的初始化结果不得把用户退回首页。
    方向选择与用户澄清在对话区完成；工作区只展示当前成果，不列出每份历史版本，不放创作决定表单。准确方向已可选择时，附带的待答问题不得盖住选项；两者都显示在对话区。仅当 direction 的用户 local_design 事项与正式待决的 stage、version、artifact_sha256 全部匹配时，可作为同一决定卡的折叠设计补充阅读，意见沿已有修改入口提交，不再另画回答表单。此展示不推断两个问题是同一决定，不标记已答、不删除原稿或写入批准；商品选择、事实问题、无类型及旧版或指纹不符的问题保留独立回答。普通继续沿用同一参考时不得仅因角色改写 `reference_scope` 措辞而推进来源世代；用户明确修改参考范围才重选。
    已有有效需求、创意方向缺失或过期时，界面的「重做创意方向」走绑定当前上游输入与旧稿版本的显式阶段命令；程序校验、派导演并停在新方向供 Jeffery 点选，不再把固定继续提示词交给主制片重新选择工具。用户有新的事实或修改意见时仍走自由对话。相同请求 ID 只对应同一次任务，服务重启不自动重发；来源或上游变化须拒绝旧页面命令。导演只收到本任务必要的当前目标、来源与简短旧稿对照，交付三个可比较的简明方向，不扩成逐镜头方案。

    因为任务结束路径先持有 `jobs.lock`、再经 `_event` 取 run 锁；已持有 run 锁的调用方
    （如 timeline）若再调 `jobs.busy()` / `jobs.get()`，就构成 ABBA 死锁——2026-09-30 实测：
    一个 `jobs.busy()` 让全部读 run 的接口冻结、`/api/runtime` 仍正常，任务线程与请求线程
    分别停在 `_event` 与 `busy`。需要运行态标志时，在获取 run 锁**之前**取快照并传入
    （见 `http_runs.timeline` 的 `job_busy`）。排查挂起用
    `scripts/serve_with_stacks.py` 启动：它按 `faulthandler` 周期转储所有线程栈，
    直接读出锁的持有者，而不是靠猜。

27. **对话输入完整保存，忙闲不改变用户身份和命令。** 原话、展示凭据、作品目标、附件用途和

    目标、模式及已上传附件引用，未知接受结果沿原 request_id 查询，不重传附件或另建请求。
    进度查询从当前运行/制作状态回答，只有真实关联回复后标为 answered；接收不等于回答。

    局部修改边界、具体交付及附加条件都须与真实原话/显式操作核对，不能只校验模型自己声明
    的计划。任务解释的条件命名须在工具定义明确为带点的内容名称（如 visual.setting、script.duration），语法错误与受保护的权限/商品事实名称分别报错；不得把格式错误笼统报告为越权，也不得自动把无效名称改写为有效权限。
    陈述或提到选项不代表采用；不确定时一次澄清。 任务解释的 ambiguity 只表示真实原话仍缺少、且阻止执行的具体信息；明确的范围限制、保留要求与执行方式放在 value/scope，明确时 ambiguity 为空。输入替换的 supersedes 与既有条件替换的 constraint id 是两种身份，不能混用；解释字段说明须明确此边界。非空歧义继续阻断，不能由服务端清空或改成确认。当前真实 produce/revise 输入已保存的适用条件首次进入 needs_clarification 时，立即结束本轮工作批次，显示该来源的具体歧义及真实冲突依据，同批剩余工具记为未执行，不再调用模型、收尾或自动派工；交付仍未完成，不生成决定或授权。讨论、状态查询与其他输入不继承旧阻断，已绑定历史解释保持原样。相关角色自动得到带来源的本轮约束，
    条件随接续传递，完成检查针对约定交付；角色隔离、准确版本及独立执行授权继续适用。

    每次主制片模型请求使用当时的真实任务解释、适用条件及已选范围投影；绑定和范围成功后，历史压缩不能让 system 继续宣称未解释或未选择。投影来自同一主任务的服务端字段，包含原来源、准确解释、范围状态及已派阶段，不能从模型摘要补造。固定方法与上游正文不因这层投影重复重建；原来源仍钉住、工具配对及每请求冻结清单继续核验。投影只说明已发生事实，不选择范围、写入决定或增加工具、执行权限与调用额度；专业角色和工具无关的默认循环保持原固定 system。
    共享任务解释说明须明确 stages=[] 仅表示本条主回复域，不表示全部创作阶段；项目或产物条件
    应列明 STAGES 中实际适用的非空阶段，可覆盖本轮 allowed_stages 之外的未来创作阶段，
    但条件范围不授予执行权限。原引用、来源、已绑定解释及条件形状校验继续按原顺序执行；
    在原空阶段作用域拒绝点，对合法形状的同类错误一次给出有界 constraints[index].scope 路径，
    不回显未知名称、值或引用，不自动选择阶段、改值、删条件、重试或放宽接受集合。
    本轮主回复的条件明确使用 lifetime=turn、stages=[]、paths=[]，不绑定或授权任何创作阶段；非空 stages 继续原产物条件。回复与产物的冲突、替换、撤销及查询隔离，空阶段不能作为任意产物范围的子集。回复条件沿原解释保存真实引用、来源指纹和身份，仅进入该来源的主制片回复；新输入、创作角色和图片观察数据报告不继承。结构化回复限制沿原 key/value 表达：reply.format 为 markdown_table 或 text，reply.table_rows 与 reply.max_chars 为规范整数文本，数字必须与真实引用核对；含义仍由模型解释，不用关键词猜意图。最大长度按最终完整字符串的 Unicode 码点计数，含表格标记、空白与文件名；表头和分隔线不计数据行；合法单列表格同样有效，普通竖线或 --- 分隔文本不当作表格。写稿收尾仍只向准确主制片来源传递回复条件，不传给写稿角色，且用户明确格式优先于默认段落安排。已绑定本轮回复条件的主制片工作与收尾均保留模型答复的首尾空白；其余旧调用维持原 trim 行为。表格核对遵循当前回复 Markdown 可呈现的单表子集：表头及数据行以 | 开头，不把未支持的写法记为格式满足。最终真实回复只检查、不截断或改写；不符合时保留原文、观察与实际用量，明确交付未完成和原因，不自动调模型补写或重读图片。历史解释与严格请求不改写，不新增创作权限或扩大工具清单。

    任务解释的共享工具说明须在首次调用前明确：task.quote 与条件 quote 是本条原话的连续引用，不能拼接、转述或省略；task.format 与 reply.format 是不同字段，回复固定格式使用准确 value，数值条件自己的 quote 须包含对应数字及单位或上限。仅同条可信、已执行且首次绑定的完整安全提案，可在落盘前聚合连续引用、固定回复值和数值引用见证的固定字段错误；预检不改值、不删条件、不判断意图或授权。已有解释不可改及原权限、冲突、来源与状态校验继续优先或完整执行，预检通过不代表这些检查通过。错误回执有界且不回显模型正文，整份解释未接受时零写、零观察，不另加模型调用或扩大工具清单。

28. **Agent 运行身份与创作产物分离，同源持久记录。**
    旧 Store 已能保存并读取的 `Artifact.attempt` 正整数保留原值、原件与读取兼容，不视为损坏；
    该例外仅限此字段，排除 bool、零、负数及浮点数。新产物写入在落盘前要求非空字符串任务身份，
    不再接受整数；历史兼容不生成新身份、修补文件或放宽其他持久化字段。
    所有项目事件的序号分配与追加由 Store 在同一 run 的可重入锁内完成，读取使用同一锁；不同 Store 实例指向同一项目时共用锁。角色并行、图片观察与请求诊断不得生成重复序号或让 SSE 游标漏事件。此保证仍限单进程，不能替代数据根 writer 锁或声明跨进程写入支持。 同一次锁内只读请求可共享已经核验的局部阶段投影，避免递归重复读取；2026-10-09 迭代允许只读事件解析缓存：由文件身份、长度与修改时间戳校验，原日志追加后立即失效，下一次读取重新解析；外部变化重新读取；返回深拷贝且不作为第二事实源。作品指纹、损坏隔离与写入健康检查仍按原路径执行。
    确定的单项目持久化损坏须只读诊断并隔离，不阻止工作台启动或其他健康项目使用；坏项目仍可见，标明项目、相对文件、固定错误类别及位置/指纹，禁止其继续写入或模型调用。不自动截断、修补或删除原件，不输出原日志内容。启动后新发现的损坏也沿同一边界阻断；费用记录无法读取时明确汇总不完整，不把该项目当零。根配置、写入锁及未知程序错误仍照常报错，不能被逐项目隔离吞掉。 主会话、用户收件与专业角色任务复用
    原事件库；角色任务绑定原 attempt ID、父任务/用户消息、方法与上下文引用、工具白名单和
    准确产物回执，明确 queued/running/waiting/completed/failed/cancelled/interrupted。
    专业角色 completed 必须有实际提交的产物；主会话结束仍按本轮交付契约判断。当前候选草稿若沿准确产物任务、回执与父 Job 身份关联到 blocked/failed/interrupted/cancelled，只读界面须区分“草稿已保存”与“检查或交付未完成”，优先查看或修改，不以草稿保存宣称验收完成或催促确认继续。缺少准确来源身份时不从历史失败、关键词或模型叙述猜测质量；新版本不继承旧任务的失败。此展示不新增质量状态或批准门槛，准确候选仍可由用户明确采用，历史采用回执不改写。停止或重启
    不自动重跑，旧任务只读追溯。任务状态不替代
    Pipeline、production、决定或费用事实源。决定回执须沿准确 continuation request/job 反映已记录、执行中与结束状态，不在接续启动后继续宣称等待启动；同一用户轮的接续结论须可见，不能被父任务的首次回执永久遮住。运行中已有阶段产物真正保存时，界面沿该产物回执去重刷新同一 timeline，不等待整轮结束、不每个模型增量重读项目，并保留画布视图和布局。真实 UI 决定的回执也沿该批准的固定 request/job 就地显示接续失败与原因，不借用上一条聊天身份，不把一次开始提示保留为执行中结论。历史原始回复不改写，其他任务的结论不并入该决定。失败重复判定使用稳定错误身份，动态任务编号
    不得掩盖同一失败；上下文恢复按当前可信事实和准确产物组装，不以助手摘要创造权限。
    只读界面刷新及结束后的恢复状态读取遇到明确服务 closing 或传输断连时，只重读同一项目，最多额外重读 4 次、等待合计不超过 15 秒；超过边界保留可见的手动刷新入口。各读取来源分别保存提示与已知损坏阻断，只有该来源成功后清除其过期提示；作品读取成功不能冒充恢复状态已经读到。不得重发 POST、模型调用或用户草稿，不改变原任务状态；项目资料损坏及其他业务 409 立即显示原错误，不作为重启重试。切换项目或更新的刷新替代旧请求时，旧恢复不得覆盖新界面；成功后显示原已保存结论并保留画布视口与布局。创作者失败提示只移除已知内部异常类前缀，保留实质失败原因、停止边界与下一步；历史原记录及技术记录保留原文，不把业务错误改成泛化成功或连接问题。 新的主会话模型失败若已有安全 public_message，持久化对话沿用与 Job 相同的说明，刷新后不得退回内部英文异常文本；原异常、用量及诊断仍沿调用台账保存，旧聊天不重写。
