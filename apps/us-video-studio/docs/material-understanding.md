# 素材理解与参考迁移

日期：2026-09-21。范围：US 独立制片室。本文记录可运行能力与限制，不是视频创意效果或商品真实性证明。

## 当前路径

新增百炼北京 Omni 原生声画入口，复用 Wan 本机连接，发送视频及可用音轨，详见[接入与限制](bailian-omni-and-tiktok-import.md)。下文“视频画面观察”描述普通兼容视觉连接的稀疏抽帧路径；不能将其无音频限制套用到 Omni，也不能把新入口等同于已验证的逐帧验收。

默认创作入口：用户一句话与商品图片 → 主制片 observe_images 读取实际像素 → 带来源的模型观察供团队构思 → 同轮给出方向。一次最多 12 张、合计 7 MB，单图沿用 4 MB 与解码限制；相同字节和用途复用。使用已配置百炼 Omni 多图输入，未配置或失败则明确说明，不假装看过，不自动重试。模型观察未经人工核实，不变成人工批准或商品性能证据。

手动兼容入口：项目素材 → 分析图片 / 分析视频画面 → 核对并采用候选观察。视频声画和参考视频入口见声画文档；两种入口都沿用原事件日志与台账。

视频沿用图片分析的连接选择、显式发送、原 JobManager/Ledger、幂等提交及逐条采用。不是新建 Agent，也不是独立任务数据库。后台对每次实际模型输入保存的逻辑请求快照包含抽帧像素；事件只保存观察、帧指纹、时间及原 call_id，不放图片编码、原视频或认证对象。

## 视频画面观察

- 输入：当前项目 MP4 / MOV / M4V / WebM，最多 64 MiB、90 秒。使用 [PyAV 18.1.0](https://pypi.org/project/av/18.1.0/) 的本地解码能力，运行依赖已锁定；普通图片分析不依赖系统 FFmpeg 命令。按 [PyAV 帧时间定义](https://pyav.basswood.io/docs/stable/api/frame.html)保留原始时间戳及相对第一帧的时间。
- 本地最多提取 12 帧，较长视频优先覆盖 0、1、2、3 秒附近，再分布到后续及结尾；实际时间取解码帧，不能把采样目标冒充实际帧时间。画面最长边缩到 768 像素，以 JPEG 发送，细节可能损失。保留旋转修正和实际输入图像指纹。
- 仅发送缩小后的抽帧、时间/覆盖信息与观察要求，不发送原视频、音频或项目聊天。音轨检测只说明容器里有音轨，不说明听过或识别过声音。
- 明确保持 `frames_observed`，不升级为 `audiovisual_review`。不能据此认定准确对白、语气、连续动作、切点、完整节奏或声画表演。用户已有人工看听和转写记录仍独立保留，不自动融合成“模型完整看听”。
- 单次调用使用明确选择的视觉连接；协议兼容不证明模型能识图或画面理解质量合格。工具返回非法帧引用、无依据机制或非完整结果时不保存候选，不自动重试；实际用量仍按原台账记录。
- 解码、像素、时长及处理时间有上限；本地失败在请求前停止。分析后素材字节改变时，旧观察不能采用。解码发生在独立任务中，可逐帧响应取消；不会因打开素材页而自动调用模型。

## 参考怎样进入创作

一次视频分析分成两层：

1. **实际观察**：可见内容、准确帧 ID 与时间点。
2. **机制假设**：引用哪些观察、可能借鉴的画面功能/证据顺序、不可移植的身份/商品/流量因素，以及下一次需要验证的表达改变。

这来自现有 [商品创意策略](../../../.agents/skills/us-commerce-strategy/SKILL.md)与[口播动作方法](../../../.agents/skills/us-creator-video/SKILL.md)的四层参考学习方式。参考分析不修改当前案例库或采用状态；它只属于本项目素材观察。

用户只采用部分观察时，需要未采用观察支持的机制不会进入依据。采用的是可见观察，机制仍明确为待验证解释，不冒充用户已经认可该创意策略。商品用途不允许夹带参考迁移机制。

[`creative_evidence.py`](../studio/creative_evidence.py)从原观察清单派生创作前视图：商品观察、参考观察/方法、未分类观察及缺口。按任务需要派出的导演、素材统筹和编剧会收到各自必要的整理；每条有 observation_ref 和原素材字节指纹。原观察正文只发送一份，避免与素材列表重复注入。

商品观察不等于商品性能验证；参考中的主张和经历不能变成本款事实。生成图片不会被归入商品事实依据。没有观察时明确说明范围和团队下一步；仍允许讨论标注了假设的想法，不把缺证据变成普遍禁止创作。

## 固定评估样本

可重复运行的六类业务输入见 [场景集](../tests/fixtures/creative-evidence-cases.json)：未观察的视频、仅转写参考、参考性能说法、生成商品图、旧字节照片、当前可见商品特征。它们使用合成文本，检查信息真正进入导演首轮输入时的分组和来源，不测模型文笔或成交效果。

另有真正编码的红/蓝场景视频和合成音轨，在测试时生成至临时内存/目录：验证解码、像素、实际时间点、音轨检测与音频未发送，以及模型边界、合法引用、部分采用、取消、超长/损坏视频和旧版本拒绝。只替换模型推理为假实现，解码与 HTTP/台账/证据流程实际执行。

验证：完整 Python 回归 1031 passed、2 skipped、1 warning；前端 263 passed。浏览器使用临时数据根及假模型走通视频分析、查看结果与采用；没有真实模型调用或媒体生成。发现并修复完成栏两个按钮遮挡问题，并更新相关静态资源版本。

## 尚未完成的能力

普通兼容视觉路径只观察稀疏画面；新增百炼 Omni 路径可传视频与音轨，其代码、服务加载和未实测范围见[声画接入](bailian-omni-and-tiktok-import.md)。连续全片可靠覆盖、自动成片验收和真实模型创意质量评估仍未完成。真实验收应比较同一业务输入下的观察准确性、遗漏、错误迁移、人工纠正次数和已知调用成本；不以离线通过率替代真实能力结果。

本节所记抽帧开发验证当时未重启真实服务，未修改真实项目素材、观察或批准。后续本机 PyAV 已补齐，但这不证明所有新增接口已加载；当前运行状态统一见[实现与验收状态](product-improvements.md)，不以这段历史记录推断当前部署。
