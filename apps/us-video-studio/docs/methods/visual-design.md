# US 人物、场景与共同视觉设计方法卡

适用：本工作台的 US 视频与图文创作，包括人物交流、情境演绎、手部演示和纯商品画面。沿用 [US 商品创意策略](https://github.com/Jeffery-Tan/e-business/blob/main/.agents/skills/us-commerce-strategy/SKILL.md)、[US 口播与动作分镜](https://github.com/Jeffery-Tan/e-business/blob/main/.agents/skills/us-creator-video/SKILL.md)和[US 图文方法](https://github.com/Jeffery-Tan/e-business/blob/main/.agents/skills/us-photo-copy/SKILL.md)。本卡是这些方法在现有阶段和实际制作输入中的承接规范，不是已验证的美国消费者偏好或市场效果结论。

## 从购买处境形成视觉选择

先明确这次内容面对谁、在哪个购买或使用时刻、现在用什么办法，以及本款哪项可见依据可能改变判断。美国市场和美式英语只是范围，不能代替具体生活处境。人物、空间和画面形式必须服务于这个理由。

依据分开记录：用户实际要求与已读商品事实保持来源；受众、人物身份、生活细节与地域呈现中没有证据支持的部分写为创作假设。不要从 US 标签推断国籍、族裔或外貌，不默认白人，也不借人物故事编造真实购买、长期使用或他人推荐经历。

美国语境由与本次处境相关的生活行为、空间尺度与布局、着装、物件和交流关系共同建立。写 US、American、放国旗或套地标不能代替设计；也不要沿用无依据的街景、文字招牌或参考人物身份。纯产品棚拍可以用中性环境，但说明为什么这种环境与视觉表达适合本次受众，不强塞美国街景。

## 原阶段中的责任

- 导演在方向的 `audience_moment` 说明具体购买处境与当前替代，在 `story` 概括说话者关系、日常环境概念、动作推进与商品作用。没有人物时说明纯商品画面如何表达。方向阶段保持简短，不提前做逐镜脚本。
- 素材统筹在采用方向之后完成具体人物、场景、服装道具与共同连续性设计，和素材需求一起保存在原 `material_plan`。设计工作由团队完成，不要求用户填写设计表或逐项审批。
- 编剧读取同一设计，以人物与场景 ID 写各镜或各页的动作、交流、声画和商品证据，不在每镜另造一套人和环境。需要改变共同设计时交素材统筹更新，再检查受影响的脚本。
- 主制片检查从方向、素材设计、脚本到完整实际输入的承接。缺设计时先派素材统筹补齐，再写或更新脚本；不把缺口交给生成模型随机补全。沿用现有四阶段和用户决定、准确图审、费用授权，不增加角色、阶段或逐项确认。

## 共同设计的单一来源

在 `material_plan.structured.visual_design` 保存：

| 字段 | 需要表达什么 |
| --- | --- |
| `schema_version`、`market` | 固定为 `1`、`US`。 |
| `audience`、`everyday_context` | 本次受众与购买/使用处境，和方向一致；未知的受众选择标为假设。 |
| `localization` | 哪些具体视觉选择承接上述处境，哪些仍是假设。不能只写“美国风格”。 |
| `style` | 构图、视角、质感与表达形式为何适合这次内容。 |
| `product_appearance` | 当前资料支持的商品形态、颜色、可见结构与不能补造的未知细节。 |
| `characters` | 每个实体包含 `id`、`label`、`relationship`、`appearance`、`wardrobe`、`performance`。关系写推荐资格或交流关系；外貌、着装和表演写可复用的具体设计。 |
| `scenes` | 每处环境包含 `id`、`label`、`location`、`layout`、`props`、`lighting`、`local_details`。布局支持动作，物件支持表达，不堆无关布景。 |
| `continuity` | 跨镜或跨页需要保持的商品、人物、服装、物件、空间、光线与动作衔接。 |
| `assumptions` | 对人物、环境、地域细节与制作可行性作出的创作假设；不能写成用户已经指定或市场已经验证。 |

人物与场景 ID 在同一设计内唯一且稳定；修订同一个人或场景保留其身份，新增实体才增加 ID。所有人物/场景行字段与 `props` 均为字符串；`continuity`、`assumptions` 为字符串列表。

`characters=[]` 明确表示不出现人物、只展示商品细节；`scenes` 至少一条。手部出镜可以作为人物实体，外貌写需要保持的手部特征，服装写可见袖口等，不强制设计完整面孔。设计中有人不代表每镜都必须有人。

脚本每段必须显式保存 `character_ids` 和 `scene_id`。前者是逗号分隔的已有 ID；该镜无人时用空字符串。后者指向已有场景。`picture` 继续写实际动作和画面，不用 ID 替代可读分镜。图文按页使用相同身份引用，仍不强迫视频时码、声音或时长。

## 检查真正会发送的输入

把该镜引用的共同设计、商品依据和完整动作声画放进实际图片或视频输入，再检查购买处境、人物关系、场景、外貌、服装道具、商品形态、语言与跨镜连续性是否承接。解释里写过而实际输入没有的内容仍算缺失；绑定版本和哈希不能替代内容核对。

图片的 `continuity` 参考用于单张静态画面的连续性与修改：按本镜追加说明保留指定元素、修改指定部分，明确要求改构图时不得把原构图固定下来。图片参考用途不代表用户已批准该图，编译模板不能写成获批首帧或要求动画。视频仍只使用经准确字节图审的单一首帧，保留其身份、商品、服装、环境与构图，并仅呈现指定动作；图片修改不放宽视频图审。

图片连续性参考规则更新后，版本仍由完整编译文本与既有制作输入指纹区分，不新增或迁移共同设计 schema。使用旧 continuity 模板的冻结图片输入会在重新编译校验时失效，须显式保存替换当前输入的新版本，再核对新输入与费用确认；不能自动改写旧稿、沿用旧执行授权或以旧错误模板继续生成。不含 continuity 参考的图片输入及视频编译文本保持原样，旧稿、图片和调用记录保留可读。

只调整参考图或模型参数且要求原描述不变时，使用原 `prepare_production` 的 `prompt=null` 和 `preserve_prompt_from={draft_id,expected_sha256}`，并让 `supersedes` 指向同一当前输入。后端在保存时核对准确父稿，再原样复制 `shot_prompt`；模型不得重抄、润色或追加说明。确实要改描述时仍提交新字符串。没有准确原描述的历史输入不能拿完整编译文本代替；保存新版本不继承旧图审或生成授权。

跨页共用场景的文字设计不保证生成结果里的空间布局相同。可以把已生成图片按 `purpose=scene` 作为环境像素参考，明确它只约束环境与光线，不能用来证明商品结构、材质、性能或真实使用；本页商品参考、动作状态、构图与文案仍各自核对。参考图中的文字或商品状态不能自动继承。一次结果相近也不能证明整组连续性稳定，仍须查看实际图片。

文字自检检查设计与输入是否一致；真实参考图检查设计是否成为可见画面。出现已知偏差先回到责任阶段修正，保留旧版本和依据，不把一次付费生成当作准备工作的替代。实际参考图展示、用户对准确版本的图审、媒体费用授权和结果验收保持原边界；采用设计或脚本不能替代这些步骤。
