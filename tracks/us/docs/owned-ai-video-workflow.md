# US 自有 AI 商品视频工作流

修订：2026-09-18。当前事实、用量、文件作废清单和下一步统一见[本轮当前整理](lunch-video-current-state.md)。本页只保留现行方法，不叠加阶段快照。

## 目标与流程

本流程是[项目长期目标](https://github.com/Jeffery-Tan/e-business/blob/59e0a850a3e8088c88f3e87185907954011d47d4/docs/project-vision.md)下的US实践：验证可重复的内容能力，同时记录人工介入、全部成本与业务反馈，不以单条素材完成代替工作流验证。有参考视频时，用本款复刻后仍须保留TikTok带货观感；平淡无错不等于满足创意目标。按[发展条件](ai-video-workflow-development-plan.md)和[参考复刻要求](https://github.com/Jeffery-Tan/e-business/blob/59e0a850a3e8088c88f3e87185907954011d47d4/tracks/us/creative/lunch/reference-remake-contract.md)决定进入下一阶段；已采用素材、失败及撤回路线只从[当前入口](lunch-video-current-state.md)读取。

建立自己掌握的“拆解爆款 → 商品适配 → 脚本/分镜与策划自检 → 参考素材/模型适配与制作自检 → 用户确认 → 生成与结果自检 → 必要补救 → 流量验证”能力，保留素材、选择理由、实际 Prompt、参数与复盘。Oumomo 是外部制作基准；Wan、H3 等可替换。用户确认沿用具体图片与费用等原有授权范围，不把每个自检点变成新的审批。

| 环节 | 必须回答的问题 | 保留产物 |
|---|---|---|
| 参考拆解 | 前三秒吸引谁，之后怎样持续增加信息、兑现利益？ | 来源、时码、画面/声音/评论；事实与推断分开 |
| 商品适配 | 哪个容量、场景、核心利益与真实结构相符？ | 15L/25L 独立参考组、素材冲突 |
| 脚本与镜头 | 每镜头新增什么信息，声音怎样跨镜头推进？ | 整段时长、Hook、镜头顺序、物品状态、台词 |
| 策划自检（出图前） | 开场期待、逐段推进和回报是否成立，角色怎样演，商品为何出现？ | 下文规定的证据、结论与必要修订；先解决脚本已有问题再生成参考图 |
| 模型适配 | 先按合理动作比较有实质取舍的方案，再决定图片/视频参考或首帧模式怎样完成镜头任务 | [方案选择与提交前复核](ai-video-recovery-policy.md#方案选择与提交前复核)、素材角色、官方依据、实际参数和 Prompt；技术预检不代替选择依据 |
| 制作自检（送审及提交前） | 实际参考图、分镜、Prompt 和声音方案能否共同支撑上述作用？ | 对照实际版本集中复核；已知准备问题修好后再作为可执行候选送审，提交前复核版本未变 |
| 图片审核 | 用户是否确认自检后的具体版本？ | 展示原图与集中自检结论；改图/新尾帧重新审核，自检不代替用户确认 |
| 结果自检与生成验收（交付前） | 原速是否有节奏，商品与物品是否可信，声音是否正确，预期回报是否兑现？ | 回执、原片、集中问题和结论；未实际检查项明确保留未知 |
| 缺陷诊断与受控补救 | 哪些问题可接受、可剪、需编辑/补镜或应停止，是否保住带货作用？ | 成因证据与推断、集中处理方案、音画区间、费用与复查，见[补救规则](ai-video-recovery-policy.md) |
| 流量测试 | 哪类场景、利益和 Hook 得到真实响应？ | 版本对应真实指标，不伪造发布或因果结果 |

一致性固定商品身份、几何与物品状态，不要求整条视频固定机位或禁止切镜。单动作分段只是局部排错/补段方法，尚未验证为整条视频默认路线。原生多镜头有官方能力依据，见[方法核对](https://github.com/Jeffery-Tan/e-business/blob/59e0a850a3e8088c88f3e87185907954011d47d4/tracks/us/research/2026-09-11-lunch-native-multishot-method.md)；本款已形成v2受控轻剪可用基线，节奏与真实性的稳定重复能力尚未验证。

分镜规划必须清楚，但不要求每镜头先生成静态图片。图片参考与视频参考均可选；首帧、首尾帧和全参考模式按接口组合规则使用，不混用不同模型的专用语法。

## 无用户参考时的自主提案试验

2026-09-17 起，低成本文本策划可与参考复刻、媒体稳定性验证并行。没有用户参考时，主 Agent 先从当前事实和采用/否定记录建立需求，自主找必要来源、说明实际阅读/观察范围，内部淘汰弱方向，再交一个可推荐的具体方案及确有区别的备选；不默认让用户提供开场和回报。商品事实需有依据，原创表达允许作为假说。第一轮校准及来源见[25L自主提案v1](https://github.com/Jeffery-Tan/e-business/blob/59e0a850a3e8088c88f3e87185907954011d47d4/tracks/us/creative/lunch/R25-autonomous-proposal-v1/README.md)。

自主提案不表示生成或创意能力已通过。所选方案确定后，主Agent负责保住开场期待、推进、回报和商品作用；下游实现困难时提出保住表达的替代，不逐步删成普通展示。提案选择不代替具体图审、费用和发布授权。经用户2026-09-18明确要求，项目方法已初步封装为下节三项Skill，仍需真实任务验证；反馈按[发展方案](ai-video-workflow-development-plan.md#补救与指标)记录，任务状态仍在飞书。

用户新链接先登记pending，同视频ID/hash去重；参考复刻的输入、输出、用户反馈归为同源对照，不算多条独立成功。只有实际观察过的内容才能提炼，ASR/抽样帧只能支持相应语义/画面结论；当前无完整声画听评合格范本，不擅自调用付费分析或恢复生成来填补未知。新结论需要反例条件，未见题验证仍按[发展方案](ai-video-workflow-development-plan.md)执行。Oumomo受限对照与图文工具的使用方式见学习入口。

实际使用时按[输入执行说明](../creative/learning/execution.md)把传播任务、案例取舍、说话方式与分镜保存在同一brief，由 `scripts/creative_brief.py` 产生实际Prompt并在提交前校验最终文字。每镜的语言作用和预期可见证明进入实际输入，改文字不能继续沿用旧编译结果；结构校验不代替内容自审、参考图批准或费用授权。当前为本地前置检查，尚非所有旧API路径的强制集成；研究分支不能替代正常成片验收。

## 生成前节奏预算：25L反馈形成的待验证改法

2026-09-16，Jeffery连续认为原速、1.1倍与1.25倍偏慢，认可1.5倍“差不多”，并要求思考如何在生成时让动作、讲话更紧凑，减少为后期压缩掉的时长付费。这是本条种草视频的节奏校准，不是所有视频统一1.5倍或统一短时长的规则。具体输入和计算见[本轮节奏复盘](../creative/lunch/R25-content-plan-v1/A-v7-continuous-script.md#生成阶段节奏复盘与下一轮方案)。以下属于下一次已授权制作时采用的准备方法，尚未经新生成验证，不触发重生成当前成片。

- **先定希望交付的节奏与时长，再分配生成秒数。** 根据用户认可的参考/既有成片反推本条节奏，不先选择宽松的20秒＋15秒再填满动作。记录台词量、整段时长、有效动作和有用途的停顿；口播词数只是预算，不能替代听感。本条同内容下一轮可先拟前13秒＋后10秒，约23秒；不是已证明能稳定生成的时长。
- **台词和动作重叠编排。** 一条语意可以跨镜头、跨回手推进；不用“说完一句→做完整动作→看家人反应→再说下一句”作为默认串行结构。开始时手已接触目标，保留抓握、越沿和落稳等能证明商品使用的关键过程；可省略无信息的伸手前等待、空手返回、重复整理与动作后的展示停留。不要为缩时删掉关键接触证据或把所有物体同时搬动。
- **把快写成可执行的时间安排。** 每段说明动作起点、何时完成有意义的状态变化、台词怎样连续衔接；用“快而清楚的日常讲解，短句间停顿，边说边连续操作”等明确表演说明。同步删除相冲突的宽松秒数或不必要停留要求。“brisk”单词、语速数字或“same voice”都不是模型保证；本轮音频参考为旧原速，可能也提供了慢节奏线索，但因果未验证。
- **在同一份准备记录里做一次低成本时间核对。** 将实际口播与动作时间线一起压到目标秒数，确认不是光压duration却保留过量动作。需要声音参考时，优先使用已获用户认可节奏的现有声段，而非另买TTS；保持原生声画路线。内部预算/既有媒体处理不新增静态预演审批、图片或任务台账。现有图是否仍支持新动作起点按实际判断，不因改节奏机械重出全套。
- **下一次正常制作验证改法，不单独花钱证明口号。** 在原有单次费用批准中用目标时长提交，记录原片原速是否可用、最终采用倍速、实际提交/返工成本及用户节奏反馈。若仍必须大幅加速才能采用，标记为后期补救成功、原生节奏未达标；不把这次1.5倍后期结果当成“原生23秒已验证”。成本改善按全部实际生成与返工计算，避免短一条却多返工几条。

Jeffery另明确：仅调整已看过片子的播放速度时，导出后直接展示即可，不再跑一轮抽帧、ASR与画质对照。这项偏好只覆盖同一片子的单纯速度试版；继续沿用原片直出和既有导出配置，不将其扩展为新生成或实质改剪免于自审。

## 剪辑与导出画质保护

2026-09-16，Jeffery要求记住25L剪辑压缩问题，避免再次发生。以下适用于后续US视频的所有剪辑工具；属于助手执行和交付自检，不增加用户审批。

- **始终回到原始媒体导出。** 原片原字节保留，修改剪点从原片重出，不把上一版有损成片作为下一轮画面源。预览压缩版与交付母版分开，预览文件不能冒充最终交付。
- **检查整条编码链。** 导出前核对输入准备/Normalize、中间文件、合成及最终编码的实际参数；不得直接沿用未经验证的默认压缩。需要中间文件时采用无损或已验证能保留细节的格式，避免连续有损转码。单纯提高最后码率、quality或分辨率无法恢复前面已丢失的细节。
- **纯剪切优先从原片一次高质量编码。** 能准确保留所需剪点和同步时可无重编码拷贝；不能为了拷贝而把剪点挪到关键帧或引入音画错位。需要重编码时显式设置质量，保留源尺寸/帧率，除非编排明确需要改变。25L的H.264 CRF14/slow是本次验证起点，不是所有素材统一的质量保证。
- **交付前实际对比画质。** 同一已看片仅调速、沿用已验证导出配置时，按上节用户要求直接展示；其他新导出核对尺寸、帧率、码率、文件大小及编码参数，并按剪辑映射将原片与导出对应帧以原尺寸比较，覆盖商品细纹、脸/头发和运动或剪口。码率明显下降须查明；尺寸相同、码率高、成功解码、PSNR或ASR通过都不能单独代替细节检查。保留同帧证据及检查范围于现有run审阅记录。
- **发现明显压缩损失，先纠正再作为合格成片交付。** 不用放大/锐化/AI补细节冒充原始清晰度恢复。实际工具或导出方式改变须如实说明；未验证的部分明确保留，不宣称已实现自动画质放行。

Hypit 0.1.8默认Normalize加standard渲染的两次有损压缩路线不再直接用于交付。本地安装尚未修复该限制：纯剪辑沿用Hypit剪点、从原片直出；含字幕/合成的工程须先验证中间资产及最终细节。具体证据见[Hypit编码保真限制](https://github.com/Jeffery-Tan/e-business/blob/59e0a850a3e8088c88f3e87185907954011d47d4/tracks/us/docs/hypit-workflow-integration.md#25l剪辑实测默认编码保真限制2026-09-16)。

## 必经自检流程

2026-09-15，Jeffery明确要求将自检固化；此前两次均在用户提醒后才补查制作方案。自检由助手主动触发，适用于US功能介绍、种草与场景/创意视频，以及会改变表达或输入的补镜、编辑；风格不同就调整观察重点，不套用固定时长、镜头数或口播字数。局部改动只复查受影响项及其对全片的牵连。

### 三个触发点

1. **策划自检：生成参考图之前。** 对照目标、可用参考、商品事实与实际脚本，先检验观看动机、信息递进、使用利益、表演和声音。明确每张待生成图必须提供的动作起点、构图与表情。没有新增图的路线，在确定输入素材前完成同样检查。已有脚本能看出的薄弱点先集中修订，不留给视频模型临场补救。
2. **制作自检：整套方案送审之前，提交视频之前。** 亲自查看实际图片/视频输入，对读最终分镜、实际 Prompt、声音设置与请求参数；有静态分镜则按计划时长查看，注明没有真实动作或声音的限制。检查下表各项，解决已知准备问题后，再一次性展示具体图片、集中结论与执行范围。提交前确认这些版本仍一致；图片、动作、时间、声音或输入角色改变，复查受影响判断并核对原授权是否仍覆盖。新/改图片始终沿用原有版本审核。
3. **结果自检：原片返回后、交付之前。** 对照前两次的预期与待实测项，检查真实输出的开场、推进、商品、表演和声音，再集中决定可用、待验证、需补救或停止。同一已看片的纯调速试版按[用户明确的交付偏好](#生成前节奏预算25l反馈形成的待验证改法)直接展示；其他剪辑或转码，交付前同时执行[剪辑与导出画质保护](#剪辑与导出画质保护)，不能仅凭尺寸相同放行。检查能力不足如实标注，不让用户承担默认找错职责。补救沿用既有次数/费用和[缺陷诊断规则](ai-video-recovery-policy.md)，自检发现问题不自动触发新的剪辑或付费调用。

### 放行依据：先证明表达，再检查执行

2026-09-15午休替身v2在已有三阶段自检下仍被错误推荐并交付，Jeffery反馈“莫名其妙”，随后要求检讨工作流及浪费的成本。[本轮追责与已有案例校准](https://github.com/Jeffery-Tan/e-business/blob/59e0a850a3e8088c88f3e87185907954011d47d4/tracks/us/creative/lunch/scene-lunch-double-v2/result-review.md#工作流复盘与处理)表明：检查项存在不等于有效；此前记录把作者想表达什么、画面是否具备演出条件，当成观众能够理解的证据。以下替换这种放行方式，不新增用户逐项审批。

**出图前，先做一次只用现有文字和素材的表达检查。** 沿用beat-plan，在关键转折旁并列写清“观众实际看到／听到的内容”和“凭此能理解的变化”。创作说明里的information、笑点解释、内心活动不能充当片内证据；允许片内正常标题和对白，但不靠助手在片外补充解释。对同一材料先作简短复述，再对照目标，找出需要自行补足的连接。助手已看过剧本时必须称为自审，不称独立盲测或真实受众测试。

放行判断只需集中回答：观众起初看懂什么、为何继续看、关键变化如何承接前文、结尾具体回报是什么，以及与本条商品内容目标有什么关系。某一关键判断只能复述作者意图时，结论为需修改，先停图像及视频生成。再问一次：**假设模型完全按稿执行，当前问题还会存在吗？** 若仍需要补人物关系、重写笑点或解释突兀转折，这是策划问题，不得转交模型或字幕补救。荒诞、超现实及类型戏仿允许不合现实；检查的是观众能否接受并跟上作品自身规则，不要求所有人物理性，也不把真实物理因果强加给所有创意。

本轮修改后的脚本必须重新检查整条表达，不能仅核对被改镜头。删段、压时长、换台词、减少角色都可能删掉铺垫或对照；“动作更少、图更容易生成”不能直接推出故事更好。商品可以作为场景线索，不强制成为笑点或每镜讲功能；但应明确本条是要让人记住什么，不能以包在画面里证明商业作用达标。参考原片未实际观看时，不据报道或自己的设想宣称节奏机制已验证。

**进入试验前，说明花这笔钱要解决什么。** 明确本次最重要的未决问题、已有依据、什么结果会让方案被否决，以及否决后的停止动作。结构、表演和生成能力等多个关键未知叠加时，先用现有参考、读稿或现有图的时间预览降低不确定性；这些准备的限制照实写，不能冒充真人演出。只有实际运动或原生声音才能回答的问题，才进入有界生成。若现有能力连结果是否满足该问题都无法判断，生成前就标明无法验收并暂停这项验证，不能先花钱再以“待用户看”收尾；能够独立判定的工程试验须明确其有限目标。试验长度服从待验证的完整表达，不默认生成全片，也不机械裁成3秒。已有费用和图片审核规则保持，用户批准授权的是试验，不替助手承担推荐质量。

**原片回来，先做内容判定，再决定是否做后期。** 第一遍按实际视频、原音及已计划的片内文字检查观看体验，随后用抽帧／ASR定位问题；不先拿Prompt逐项找“已出现”的证据。工具不能实际消费原速声画时，明确这项检查没有完成；若语气、停顿或口型正是笑点成立的关键，就不能凭ASR与接触表宣布创意通过或“基本成立”。原片可作为明确标注未通过／待验证的试验结果提供，不能改叫候选后继续投入包装。

已知故事／商品表达失败时停止后期；关键验收能力缺失时先说明具体缺口和现有免费检查能覆盖什么，不默认为让用户承担审片。技术通过、助手内容判断、用户本轮验收与真实市场结果分开记，不以任何一个替代其他。以已知失败案例回查规则仅算回顾性校准；有新案例实际减少误放、用户纠错与总成本后，才能声称改进有效。

### 必查内容及证据

| 项目 | 要回答的问题 | 留下的具体依据 |
|---|---|---|
| 目标与参考 | 本条要达到什么风格与带货作用；参考哪些机制有实际来源？ | 本条目标、参考来源及覆盖限制；区分原片观察、报道信息和原创推断，不凭“像广告”判通过 |
| 前三秒 | 第一眼异常/利益是什么，正在发生什么，观众为什么想看下一镜？ | 0–3秒对应画面、动作和台词；静图好看、重复强调“抓人”或加一句字幕均不单独证明Hook成立 |
| 持续推进与回报 | 每段新增什么；重复动作/吃饭/走路占多少时间；结尾兑现了什么？ | 标出时间窗口、信息变化与结束点。停顿可以承担紧张或喜剧作用，但要指出观众在等待什么；时长由表达需要决定 |
| 商品事实与故事作用 | 商品是否可信、出现是否自然，观众能记住什么用途或利益？ | 本款事实来源、关键使用动作与故事的关系；不把大面积摆在前景当有效融入，也不强迫每条创意片列功能或展示完整装载 |
| 声音与表演 | 哪个角色的表情/动作让意思成立；谁在说话；无口播时靠什么持续支撑？ | 实际台词/时间、可见脸或身体反应、声音和剪辑作用、静音字幕计划。无口播可以成立，须有具体支撑；背影、固定表情和留白对表演的限制要正面处理 |
| 输入与执行 | 参考姿态、镜头、物品起止状态是否支持 Prompt；是否要求同一状态既变又不变？ | 实际图片版本及现有hash清单、Prompt/分镜/请求版本、动作窗口、已知失败与本次差异。合理起止状态变化不是自动冲突；模型是否兑现仍待实测 |

每次同时保留支持推荐的证据和最可能令其失效的一处，不要求为了显示“认真”硬凑缺陷。多读一遍、另一代理同意、文档完整或离线测试通过，都不能替代上述具体判断。

不采用“把所有风险都列为待实测，然后可进入”的结论。待实测项须区分已有表达成立、只待模型执行的未知，与当前材料本身尚无支撑的判断；后者必须先处理。自检结论要改变下一步实际动作，不能只是随执行附上一页说明。

### 结论、修订与记录

生成前自检明确写成“可进入下一准备/审批环节”“需修改”或“停止本方案”；未执行检查就记“未完成”。**未完成或需修改时，不将它作为已准备好的执行方案送审，不上传生成输入或提交视频。** 必要的方向澄清可以展示明确标为讨论稿的材料，不伪装成最终图审。已授权的本地修订由助手完成，完成后复查；仅复查有变化的判断，不因无新证据重复全套打磨。

“可进入”表示准备达到本次试验要求，允许保留有边界的实测未知项，如纸板是否会活化、对白和喜剧停顿能否执行；不得要求先证明生成成功或保证传播。已知脚本无信息推进、参考图不支持关键表演、商品依据缺失等准备问题，须先处理，不能一律归为模型风险。已有用户明确采用的素材及已接受瑕疵不追溯返工。

沿用本次run的README、方案或审阅文件，增加同一段记录即可，不另建任务表或重复台账。记录格式：

> 日期 / 阶段 / 触发者（助手主动或用户提醒）；检查对象、版本和已有hash清单；覆盖范围与限制；支持依据与集中问题（时段、影响、事实/推断）；结论；已修订内容及复查结果；保留的待实测项、失败退出条件；下一步。

修订后的自检需绑定修订后的素材和请求，旧记录保留日期与结论；已冻结或获批文件不回写通过，使用现有run中新版本记录并按原规则更新提案。用户提醒后补做的自检如实记为补检，不算助手主动履行；结果未知不补成“通过”。向用户简要说明发现什么、改了什么、还有什么待实测，不转交逐项检查清单。

这是一项助手必须执行的制作规范，当前脚本仍只核验技术、版本与授权，尚未实现自动语义审核。后续在正常制作中记录主动完成情况、提前发现与修正的问题、用户新增纠错、实际结果及审核成本；不为验证流程额外生成。现有案例支持补检有用，尚不能据此宣称稳定提高传播率或生成成功率。
