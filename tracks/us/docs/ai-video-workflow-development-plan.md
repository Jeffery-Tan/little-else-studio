## 要形成的能力

用户给出需求后，助手先读取已有商品事实、目标及约束；没有用户参考时也承担必要参考发现、理解、具体提案与筛选。有参考时完成参考拆解与商品适配。原生声画、生成、验收和有上限的补救仍按实际授权执行。早期 US / LUN / 15L / 美式英语 / 个人工作日验证不能替代25L适配；15秒为早期参数，后续按风格与有效剧情定时长。

最低创意要求是：有参考时，用本款复刻后仍保留TikTok带货视频的注意力推进和用途证据；平淡无错仍不通过。用户认可的外部平台产物是比较基准，不是其内部技术方案的证据。技术成功、内容判断、用户采用和市场结果分别记录；内容未通过不能用“候选”标签继续制作，没有流量数据不保证爆款。

用户保留新图片版本审核、必要的集中创意判断和发布决策。助手承担已知问题检查和限额内的执行，不能依赖用户逐镜纠错，也不能把用户诊断反馈机械转成改片要求。关于 Agent 常见步骤的讨论不构成固定的额外审批链。

## 阶段与进入条件

| 阶段 | 工作与进入下一阶段的依据 |
|---|---|
| 自主提案校准 | 先交可想象实际声画的文本，记录用户是否无需补核心点子就愿意推进。首题只作校准；后续正常需求累计3个未见题，至少2个可直接/小改推进且没有已知关键事实错误被放行，作为试点观察门槛，不是成功率保证或付费批量授权 |
| 参考与商品适配 | 映射开场期待、信息递进、动作压缩和声音连接；每项用途有本款结构依据。缺失参考音频、未实测性能和不可迁移结构须明确 |
| 生成前自检 | 助手按[必经自检流程](owned-ai-video-workflow.md#必经自检流程)先审策划再出图，对照实际参考图、分镜、Prompt与声音完成制作自检后再送审；已知准备问题解决、结论绑定当前版本，才进入既有审批和生成 |
| 内容可用性 | 按精确请求验证原生声画，同时检查观看体验和商品真实性；先内容判定，再决定后期，原片与剪后分别记结果。单条采用或技术导出不等于整套方法稳定 |
| 验收、补救与重复性 | 先证明硬错误识别与受控补救不会损伤语义，再冻结方法。后续建议3个事先登记的不同seed顺序验证，至少2条达到创意/商品标准，零项已知硬错误误放行、零次用户中途纠错，人工与费用不超事先上限。属于小样本门槛，不是成功率估计，也不是已授权批量 |
| 封装有效步骤 | 在现有执行器上衔接商品输入、编排、版本/审核失效、预算、结果回收、审核与恢复；一次输入到候选或明确失败，中断可恢复。界面和离线测试通过不能替代内容通过 |
| 方法迁移 | 先验证同款第二个Hook，再选择事实和素材齐备的另一US商品；频繁特殊手工救片说明方法仍未迁移 |
| 业务反馈 | 经实际发布授权后关联素材版本与可取得的留存、点击、成交口径，缺失记缺失；自然流量不冒充随机实验。数据接入沿用 Product Intel 边界，不建立第二套collector、SQLite或任务系统 |

进入下一次试验前，先按[表达放行依据](owned-ai-video-workflow.md#放行依据先证明表达再检查执行)区分观众能接收到的信息与作者意图，假设完美执行仍存在的问题先退回策划；关键结果无法验收时在花钱前停止。涉及动作实现时，再按[方案选择与提交前复核](ai-video-recovery-policy.md#方案选择与提交前复核)比较实质替代。已完成的动作决策复核和午休替身失败回查都是已知案例校准，不证明新样本可靠性；生产是否暂停、是否有待执行请求以当前入口为准。

## 验收能力的职责

| 层次 | 可以支持 | 不能据此声称 |
|---|---|---|
| 技术检测 | 解码、时长、音轨，黑帧/冻结/低音量候选 | 动作正确、声音自然或创意通过 |
| 密集帧和原速复查 | 结构、接触、物体状态、切镜是否能解释变化 | 仅凭缩略图证明全片连续动作；把未见拉头当已见运动 |
| ASR | 台词内容与近似词时标 | 精确剪辑边界、音乐品质或听感通过 |
| 辅助模型 | 语义与待检查问题候选 | 独立放行；既有整段/窗口校准已有漏检和编造运动证据 |
| 受控补救 | 按已标注问题、口播及证据保护区间预检与执行 | 自动发现问题、自动理解用户采纳或跨运行完整预算控制 |
| 必经自检与集中创意复核 | 出图前检查策划、送审及提交前核对实际输入、交付前检查输出；比较信息推进、表演、声音与商品可信度 | 自动化稳定或已有市场效果；填写完整不等于判断正确 |

每项结论须注明对象、覆盖范围、时间窗口和限制。读过缺陷标签后复述不能算盲测；修改提示词后重用同一历史样本只能记回归。没有真实听评能力，相关项保持待验证，不以漂亮分数覆盖硬失败。具体失败证据与技术边界由[当前入口](lunch-video-current-state.md)链接，方法页不重复逐次账目。

## 补救与指标

遵守[补救规则](ai-video-recovery-policy.md)：先分级，再集中选择接受、剪辑、编辑/补镜或停止，保住声音、用途证据与节奏。补救必须有该次明确的次数、删段/时长和预算边界，失败记录保留；reference-grammar-v1的“最多一次、最多1秒”属于历史已使用授权，不自动套用下一次。

| 指标 | 记录口径 |
|---|---|
| 首轮提案可推进 | 用户反馈分为直接推进、小改可用、核心重写、不采用、待定；未知为null。核心重写包括用户提供新开场、主张、人物关系或关键回报；作者自审不算用户采用 |
| 推荐与选择 | 推荐选项及版本、用户实际选项及版本分别保存；未选为null，选备选不算主推采用。校准题、历史回归、未见题分开，不重复计成功 |
| 原生通过 | 全部成功返回原片中的完整验收通过数；技术成功、待审、失败分列 |
| 请求交付 | 全部实际提交中形成合格候选的数量，API失败和未知状态保留在分母 |
| 合格结果成本 | 本轮全部已核费用 / 合格候选数；分母为0则不可计算，另报累计投入。未核仅报估算 |
| 用户介入 | 图片审核、预算/创意决定、商品补充、纠错分别计数；未知耗时记null |
| 自检履行与收益 | 各阶段主动完成还是用户提醒后补检、提前发现并解决的问题、后续用户新增纠错及实际输出；既有已知案例不算独立效果验证，审核成本沿用人工口径 |
| 人工与返工 | 主动编辑、助手修订及复核、生成等待分列；只有墙钟时间时不得冒充主动工时 |
| 错误漏检 | 用户发现而助手此前放行的硬错误单列，助手自我纠正也留记录 |
| 商业效果 | 对应已发布版本和真实观测；未发布或未取得数据记未验证 |

后期通过与原生通过分开。原生音轨的有限删段不是独立TTS重配；变速、冻结补时、逐帧修补或新生成局部片段须单列流程偏离及成本。不能把一次轻剪可用记成原片自动通过。

## 2026-09-18：小号包暴露的系统问题与暂停

Jeffery要求先停止当前小号包改稿/生成，记录三个问题。以下保存原意，不归为单条视频待修镜头：

1. 创意、口播、分镜缺少有效的系统性技能或足够案例学习，近似临时发挥；需要用户不断从方法层面纠正，否则成片不可用。
2. 定位的用户群、表演角色、需要传递的信息以及符合人设的表达方式没有形成明确联系。
3. 纠错机械、缺少理论依据，容易钻牛角尖。用户表示持续指导消耗过大，希望先解决如何系统优化。

当前小号包素材制作暂停；v14仅保留草稿，不是待催审或默认下一步重做。停止改稿、TTS、图/视频生成和当前素材后期补救，直到用户明确恢复对应工作。未选择替声或重做，不沿用已消耗的单次5.70元授权。暂停不抹掉原片、失败成本和批准历史，也不推断其他US或SEA任务一并暂停。

### 本次核对支持的诊断

- 不等于仓库完全没有方法：本页、自有视频工作流、补救规则均已存在。缺口是从证据到创意决策、实际输入和结果评价的有效执行，而不是再写一份自检清单。通用copywriting Skill只能提供原则，不能充当US达人表演的已验证能力。
- 小号包v13作者自审写了“生活化种草”，但实际文本仍是概括卖点；词速/时长预算不能证明聊天感。实际Prompt v4两处禁用lip sync，与用户期待人物交流不一致。不得把用户对v13文本的批准当作助手已验证声画表达。
- 部分历史案例拆解明确只掌握报道、摘录、有限帧或缺失声音，且有非带货内容；可以启发题材，不能证明已经学习了带货口播、停顿、表演和转化结构。案例数不能抵消证据覆盖缺口。
- 可靠原速声画听评仍未具备独立验收证据。ASR和抽帧不能证明自然表演；没有解决这一能力缺口，不应承诺助手能够独立学会并验收“活人感”。
- 用户指出原片问题后，助手立即写v14并推荐重做，仍先处理局部表达、后讨论受众与策略，属于本次机械纠错的继续。v14不记录为改进成功。

### 优化顺序（已部分落地，不是恢复制作）

1. **先定义传播任务。** 对每个商品明确：哪种具体处境下的人、当前怎么解决、有什么顾虑；视频希望改变哪一个判断；本款有什么可信证据；谁以什么关系来讲。人物外观不是人设，“Gym girl”也不等于已验证买家群。情境需求、购买顾虑、传播目标、证据与人物表达应互相支持，缺数据时标为假设。
2. **做小而完整的对照案例学习。** 首批可约12条US相关短视频作为工作量上限示例，数量不是理论保证：同类商品、同种购买动机为主，辅以可迁移的真人表达；尽可能同账号/相近商品和发布条件作对照，不只挑播放最高的。区分自然内容、付费广告、挂车与非挂车；记录指标、日期、投放/价格/受众等未知，播放或点赞不冒充成交。必须完整观看和听取原片；只有文字或摘要的留作线索，不进入口播/表演学习集。
3. **拆因果假设，不抄表面元素。** 每条回答谁为何会听、希望观众改变什么判断、人物为何有可信度、哪句是事实/态度/异议回应/行动邀请、哪段画面证明什么、声音和动作如何衔接。保留准确时码及最小必要摘录，不复制整段第三方稿件。把看见的事实、解释和可迁移条件分开，检验反例；密集口播、吐槽或开口本身都不是普适答案。
4. **形成可检索示例，再进行未见题验证。** 示例与失败对照存现有线路资料，不另建collector或任务库。案例检索用于每次新任务的输入，不意味着底层模型权重被训练。沿用本页已有3个未见题、至少2个无需用户补核心创意可推进的试点观察门槛；小样本不估计稳定成功率。方法冻结后不边看测试答案边补规则；没改善先追查解释/证据/能力缺口，不花钱反复生成。需要独立评审时不能用同源Agent相互赞同代替受众或真人判断。
5. **封装方法后继续验证，再接回制作。** 用户明确要求初步封装，已将有来源的决策方法、示例检索与反例整理成三项项目Skill；这不等于经过完整对照或效果验证。完整配音/表演的低成本检查须具有真实听评能力，明确成本和适用范围，不自动把独立TTS变成默认生产路线。文本通过不等于成片或市场通过；后续少量获批生成与真实发布数据分别验证。

评价顺序建议为：传播任务是否成立 → 表达与证据是否让目标观众理解 → 实现是否忠实 → 修复收益是否值得成本。先确认问题在哪一层，再比较替代路线，避免模型能力限制反过来删掉核心表达。“有理论”指有可说明、可反驳的判断依据，不是引用AIDA等缩写就算通过。

用户负担以已有“核心重写次数、纠错次数、人工与返工”口径衡量；助手承担找样本、核事实、拆解、筛选和自查。仅在确需判断商业取舍或校准主观观感时集中提交少量明确选项；不要求用户收集案例、填评分表或逐句当老师。若独立声音判断仍做不到，要明确作为未解决能力/人工依赖，不能悄悄转嫁给用户。

## 执行与授权

沿用精确请求批准、一次提交、状态未知时只轮询同一任务的机制。当前执行器可检查单次图片hash、请求摘要、次数和金额；跨运行总预算仍需单独实现与验证，改seed也会改变请求摘要。

新方案在需要确认前，先备齐可审阅的输入、实际请求、费用（含参考视频输入秒数）、次数、允许变更、补救和停止条件，并完成绑定实际版本的制作自检。自检未完成或需修改时不作为可执行候选送审；提交前核对结论仍对应当前输入。该要求是助手执行规范，脚本尚无自动语义审核；沿用既有图片与费用审批，不增加用户逐项批准。引用价格时核实当时有效口径；旧预算和已使用审批不得挪用，新图、付费分析、升分辨率、Prime、H3等费用须按实际范围说明。

以下情况停止提交：次数或费用达限、无新证据却重复同类硬失败、任务状态未知、输入hash或商品事实改变、必要听感/商品检查缺失、请求或计费条件超出批准范围。新图、改图或抽帧作生成输入，均先自查并展示，经用户确认该版本后才能调用视频API，见[AGENTS.md](../../../AGENTS.md)。

已经授权的本地准备、验证与记录可持续完成，不让用户反复说“继续”。生成、审核与发布各按实际授权范围推进；没有发布或流量结果时，阶段仍不能闭环。
